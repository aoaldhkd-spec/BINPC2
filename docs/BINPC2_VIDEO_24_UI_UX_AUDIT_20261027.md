## 화면 배치(Layout) 7개 — 유지·선별
1. **Hero Section(히어로 섹션)**: 소개 화면의 큰 제목·CTA(핵심 행동) 구성. BINPC2 현장 참가자 화면을 새 홍보 랜딩으로 바꾸지 않는다. MATCH 판매 안내 화면에서만 필요성 검토.
2. **Responsive Layout(반응형 배치)**: 폭에 따라 카드·메뉴 재배치. 운영 BINPC2는 320~1024px × 밝음/어두움 12개 합성 Chrome 검사 PASS. MATCH는 320~1280px 합성 Chrome PASS. 현재 구조 재사용.
3. **Card Layout(카드 배치)**: 프로필 카드·하트 및 관리자 상태 카드 기존 구조 재사용. 기존 카드 색상·사진·하트 이벤트 불변.
4. **Bento Grid(벤토 그리드)**: 중요한 정보는 큰 카드, 나머지는 작은 카드. 참여자 화면 전체 변경은 지양. 관리자 대시보드에서 실제 우선순위가 근거로 확인될 때만 후보.
5. **Sidebar Layout(사이드바)**: 데스크톱 관리 화면이나 MATCH 소개/설정에서 재사용할 수 있으나 운영 모바일의 확정된 하단 메뉴는 변경 금지.
6. **Sticky Header(스크롤 고정 헤더)**: 긴 설정·관리 화면에 선택적으로 검토하되 모달·하단 메뉴 위에 겹치거나 콘텐츠를 가리지 않도록 선 검증 필요. 무조건 추가 금지.
7. **Split Layout(좌우 분할)**: 넓은 화면 설명/설정에서 보조 용도. 휴대폰은 세로로 복귀해야 함. 기존 참가자 카드 목록 변경은 불필요.

## UI 컴포넌트 9개 — 기존 동작 우선
8. **Tabs(탭)**: 기존 하단 메뉴와 개인·단체채팅 탭 유지. MATCH는 방향키·Home·End 탐색을 독립 QA에서 검증.
9. **Accordion(아코디언)**: 긴 도움말·FAQ의 펼침/접기에만 후보. 새 패널을 근거 없이 증설하지 않는다.
10. **Modal/Dialog(모달)**: 기존 확인·동의·무지개 안내 기능 재사용; Escape, 초점/닫기/배경 복귀가 있는지 기존 기능별 검증. 개인정보 동의 절차 축소 금지.
11. **Drawer(드로어)**: 우측 슬라이드 설정/상세 패널로 적합하지만 기존 MY/설정 화면을 대체하지 않는다. 실제 좁은 화면 문제 확인 시에만 검토.
12. **Dropdown(드롭다운)**: 현재 선택/필터의 기존 구현 우선. 새 옵션이 필요한 경우에도 저장값·권한·키보드 접근 유지.
13. **Tooltip(툴팁)**: 설명 필요한 아이콘에만 한정. 모바일에서는 호버만으로 설명하면 안 되고 탭·키보드에서도 접근 가능해야 함.
14. **Toast/Snackbar(토스트)**: 저장·오류·중복클릭 등 결과를 짧게 알려주는 기존 알림과 중복되지 않게 개선. 실패를 성공처럼 표현하지 않는다.
15. **Carousel(캐러셀)**: 기존 그리드 기본값 + 이용자가 선택하는 가로 슬라이드. 좌우/모바일 스와이프/페이지 점/키보드/최대 150명 분할 로딩 유지. 이미 구현·합성 검증 완료.
16. **Skeleton Loading(스켈레톤 로딩)**: 실제 데이터 요청 중 빈 화면이 문제가 되는 영역에서만 후보. 가짜 로딩 완료/오류 감춤 금지.

## 움직임·반응 8개 — 시각 정체성 보호
17. **Hover Effect(호버)**: 마우스 커서 시 버튼 반응. 모바일 탭·초점 표시를 대체하지 않음.
18. **Scroll Reveal(스크롤 등장)**: 판매 안내/소개 같은 긴 정적 화면에서만 선택적으로 후보. 실시간 하트·채팅 화면에는 기본 비적용.
19. **Stagger Animation(순차 등장)**: 프로필 150개가 순차로 나타나면 성능·접근성 저하 위험. 핵심 참가자 목록에는 적용하지 않음.
20. **Smooth Transition(부드러운 전환)**: 기존 메뉴·카드의 짧은 상태 전환 재사용. 너무 긴 화면 전환이나 불필요한 전체 새로고침 금지.
21. **Glassmorphism(반투명 유리 질감)**: 시각 디자인 자체를 바꾸므로 사용자 승인 없는 전체 테마 변경 금지. 텍스트 명암 대비 최우선.
22. **Parallax Scrolling(배경 시차 스크롤)**: 움직임·CPU 부담 가능. BINPC2 현장 실사용 화면에는 도입하지 않음.
23. **Scroll Snap(스크롤 스냅)**: 기존 선택형 캐러셀 스냅 재사용. 좌우 넘김·페이지 표시 일치 유지.
24. **Micro-interaction(미세한 반응)**: 선택·저장·하트 전송에 성공/실패·중복 클릭 방지를 분명하게 표시. 이미 개발 브랜치/QA에서 일부 보완; 실제 송신은 운영 DB 검증 전 UNKNOWN.

## 적용 결론과 중단선
- **즉시 유지/활용:** 반응형, 카드, 탭, 모달 안전성, 캐러셀+스냅, 키보드 접근, 작은 상태 피드백, 움직임 줄이기.
- **증거 기반 후보:** 긴 설정의 아코디언·드로어, 도움말 툴팁, 스켈레톤 로딩, 관리자용 벤토 그리드. 실제 불편·영향범위를 확인한 다음 별도 검토.
- **무단 추가 금지:** 전체 글래스모피즘 테마, 과도한 스크롤 리빌/스태거/패럴랙스, 전체 프로필 목록 강제 슬라이드화.
- **확정 기능 보호:** 기존 BINPC2 디자인·이름·하단 메뉴·하트 운영 규칙·1:1 및 단체채팅·푸시 타깃·관리자/17/23/00/01시 운영·DB·실시간 동기화·기존 사용 기록.

# BINPC2 MASTER CONTEXT

옛 규칙보다 이 문서와 현재 코드가 우선한다.
대화에서 확정된 기능 기준·하트 최종 사양·어드민 운영·결정사항을 한곳에 모았다.

## 1. 서비스

BINPC2는 오프라인 행사 참여자용 현장 웹앱이다.

참여자: 입장, 프로필, 프로필 설정, 일반 설정, 하트, 1:1 채팅, 단체채팅, 알림, 통계, 랭킹, 튜토리얼/코치마크.

어드민: 하트 운영, 시간별 자동 해금, 시간 변경, 공지, 즉시 해금, 기능잠금, 참여자 관리, 행사 초기화/리셋.

실시간: `app_settings`/SSE 기반. 하트 스케줄·공지·잠금, 채팅/단체채팅/알림.

공통: 모바일 현장 우선, 서버/클라이언트 상태 일치, 운영 데이터 안전, 최소 변경, 회귀검증 필수.

## 2. 일반 하트 4종

| 종류 | 아이콘 | 사용 |
|---|---|---|
| 호감 | ❤️ | 1회 |
| 친구 | 💙 | 1회 |
| 뜨밤 | 💗 | 1회 |
| 칭찬 | 💚 | 1회 |

이름/기존 설명문은 임의 변경하지 않는다.

규칙:

- 각 종류 최대 1회. 개수 입력 방식이 아니라 잠금/해금.
- 잠금: 사용 불가. 해금+미사용: 1회. 사용 완료: 재사용 불가.
- 기능잠금은 하트를 소모하거나 지우지 않음. 해제 후 실제 해금/사용 상태 복귀.
- 기능잠금 ON이면 헤더 5종 모두 잠금 표시.

## 3. 무지개하트

- 일반 하트와 완전히 별도. 개수 직접 입력 없음. 잠금/해금.
- 해금 시 4회. 4→3→2→1→0. 최대 4회.
- 클릭 시 작은 선택 모달에서 호감/친구/뜨밤/칭찬 중 하나 선택.
- 선택한 의미로 상대에게 전달. 차감은 무지개만. 일반 하트 상태/사용량은 변하지 않음.

예시: 호감 1 / 무지개 4 → 무지개에서 호감 선택 → 호감 1 / 무지개 3.

일반 하트 모달과 무지개 모달은 목적/설명이 다르다. 무지개 모달은 작게.

## 4. 서버 출처

`likes.like_source`

- `grant` = 일반 하트
- `rainbow` = 무지개하트

미지정 시 grant 기본 처리. 서버는 grant와 rainbow 한도를 따로 판정한다.

거절 문구:

- 일반 잠금: `이 하트는 아직 해금되지 않았습니다.`
- 일반 사용 완료: `이미 사용한 하트입니다.`
- 무지개 잠금: `무지개하트가 아직 해금되지 않았습니다.`
- 무지개 소진: `무지개하트를 모두 사용했습니다.`

사용량은 실제 `likes` 기록 기준. 새로고침/SSE 재연결/중복 해금으로 부활하면 안 된다.

## 5. 해금 스케줄

기본:

- 23:00 → 호감
- 23:30 → 친구
- 24:00 → 뜨밤 + 칭찬
- 24:30 → 무지개

시간은 어드민에서 분 단위로 변경 가능. 24:00/24:30은 다음 날 00:00/00:30으로 계산.

저장 위치: `app_settings.event_schedule` JSON (v2 `unlock` 슬롯). 코드: `heart-ops.ts` / `db-heart-ops.ts`.

구 `rainbow_pool` / `heart_grants` 개수 모델은 폐기됐다. 읽기 호환(마이그레이션)만 남긴다.

## 6. 공지 / 카운트다운

참여자에게 다음 해금 하트, 해금 시간, 남은 시간을 보여준다.

스케줄 변경 시 실제 해금·공지·카운트다운이 같은 데이터를 기준으로 즉시 바뀌어야 한다.

## 7. 어드민 하트 운영

카드에 포함: 현재 하트 상태, 시간별 자동 해금, 시간 수정, 해금 하트 다중 선택, 직접 공지, 다음 해금/남은 시간 연동, 지금 해금.

일반/무지개 모두 개수 직접 입력이 아니다.

지금 해금: 해당 종류 사용 가능. 무지개는 4회. 다른 하트 상태는 바꾸지 않음.

어드민 비밀번호를 코드/문서/로그/Git에 저장하지 않는다.

## 8. 기능잠금

- 운영 중 일시 기능 제한. 사용 기록을 지우지 않음.
- 서버는 `FUNCTIONS_LOCKED`로 별도 판정.
- 헤더 5종 모두 잠금 표시. 해제 후 기존 상태 복구.

## 9. 실시간

대상: app_settings SSE, ready, 하트 스케줄, 공지, 카운트다운, 1:1 채팅, 단체채팅, 알림, reconnect.

금지: 중복 SSE, listener 중복, reconnect 누적, 동일 이벤트 2회, 공지 중복, timer 중복, cleanup 누락, memory leak, 하트 부활.

새로고침/여러 브라우저에서도 DB 기록 기준. 동일 해금 이벤트 재평가로 재지급 없음.

코드 지도의 실시간 경로: [ARCHITECTURE.md](../ARCHITECTURE.md).

## 10. 튜토리얼 / 코치마크

- 안내/하트/설정/채팅/단톡/숨은기능은 현재 기능 기준.
- 입장 후 신규 하트 설명.
- 모달 외곽 크기 변경 금지. 스크롤 추가 금지. 현재 칸에 맞춤.
- 영상/시연은 끊김/튐/깜빡임 최소화.

## 11. 데이터

주요: profiles, likes, chats, messages, app_settings, group_*, notifications, `app_kv_rows`.

이미지 바이너리는 API 프로세스 메모리 LRU(`db-image-store`)이며 KV 테이블이 아니다.

API: 하트 전송 제한, 기능잠금 판정, 사용량 계산, 설정 저장/조회, `/ready`, SSE.

`app_settings` patch가 다른 값을 지우면 안 된다. 빈 값 입력이 라이브 값을 임의 삭제하면 안 된다. 운영 DB 전체 초기화 금지.

## 12. 보호 원칙

하트 변경 때문에 채팅, 단체채팅, 알림, 프로필/프로필 설정, 일반 설정, 통계, 랭킹, 어드민, 실시간, 리셋이 깨지면 안 된다.

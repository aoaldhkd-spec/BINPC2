# BINPC2 / 하트나우 — 신청 UX·공지·포스터·속도 최적화 통합 지시

기존 BINPC2 개발 작업에서 하던 부분부터 계속 이어가.

저장소: aoaldhkd-spec/BINPC2
개발 브랜치: feat/event-hub-v6-20261027

최신 원격 HEAD와 실제 배포 코드를 먼저 확인해.
최근 UI 간결화 배포 및 동반신청 후속 작업을 보존하고, 이미 완료된 기능은 다시 개발하지 마.

Cursor는 오류로 작업하지 못하므로 Codex를 단일 코드 작성자로 사용한다. 다른 작업자의 변경이 있으면 먼저 확인하고 덮어쓰지 마.

## 1. 가장 중요한 목표 — 설명보다 버튼

현재 웹은 흰색 설명 상자가 너무 많고, 불필요한 문구 때문에 화면이 복잡하다.

카카오톡·토스·당근처럼 사용자가 보고 바로 누를 수 있는 간결한 UI를 참고해. 다만 특정 앱을 그대로 복제하지 마.

- 불필요한 설명·중복 안내 제거
- 짧은 버튼은 한 줄에 2~3개씩 배치
- 선택지가 있으면 직접 타이핑보다 선택형 UI 우선
- 필수 동의·회비·참가조건·오류 안내는 유지
- 중요한 신청·저장·입장 버튼만 강조
- 기존 할로윈 테마·로고·색감·기능 유지
- 모바일과 PC에서 여백·스크롤·버튼 겹침 해결

기존 공통 버튼에 전체 폭이 강제돼 있는지, 각 화면의 부모 레이아웃 문제인지도 확인해.

## 2. 신청 첫 화면 변경

사용자가 [신청하기]를 누르면 곧바로 긴 입력 양식을 보여주지 마.

먼저 간단한 선택창을 띄워.

“누구와 신청하시나요?”

[혼자 신청] [지인과 함께]

선택하면 해당 신청 단계로 자연스럽게 넘어가.

이미 선택했다면 같은 팝업을 반복하지 않고, 이전 단계로 돌아가 선택을 수정할 수 있게 해.

모달은 모바일에서도 읽기 쉽고 닫기·뒤로가기·키보드 접근이 가능해야 한다.

## 3. 신청방법 앞의 ? 제거

‘? 신청방법’ 같은 불필요한 물음표 아이콘을 없애.

필요하면 [신청 안내]라는 간단한 보조 버튼만 유지하고, 반복되는 설명은 기본 화면에서 제거해.

신청 절차는 실제 버튼과 현재 상태만으로 이해되게 만들어.

## 4. 연락용 전화번호는 신청 시 요구하지 마

일반 신청·프로필 작성 단계에서 연락용 전화번호 입력란과 필수 검증을 제거해.

전화번호는 **상금 또는 상품을 실제로 받았고, 전달·지급 과정에 필요한 경우에만** 요청해.

- 일반 신청에 전화번호 필수 요구 금지
- 전화번호를 안 적었다고 신청·승인·입장 차단 금지
- 상품 수령에 필요할 때만 해당 수령 절차에 표시
- 왜 필요한지와 이용 목적 안내
- 수령과 무관한 화면·공개 프로필에 노출 금지
- 기존 개인정보·인증정보 임의 삭제 금지

화면에서만 숨기지 말고 서버 필수 검증까지 확인해.

기존 관리자 로그인·본인 복구·보안 인증 기능에서 사용 중인 전화번호 구조는 함부로 제거하지 마.

## 5. 년생·사는 곳은 선택형으로

현재 프로필 설정에서 사용하던 선택형 UI를 신청 단계에서도 재사용해.

**출생연도**
- 선택 버튼 또는 스크롤 선택기 제공
- 출생연도를 직접 전부 타이핑하지 않아도 되게
- 행사별 참가 연령 정책은 그대로 적용

**거주지역**
- 도시 선택
- 부산이면 구 또는 동 중 하나를 선택
- 필요한 경우 검색형 목록 제공
- 이미 저장한 지역은 다시 입력하지 않고 불러오기

본인과 친구 각각 독립적으로 선택·저장하게 해.

친구의 정보가 본인 프로필을 덮어쓰면 안 된다.

## 6. 다른 입력란도 최대한 선택형으로

선택 가능한 정보는 다음과 같이 바꿔.

- MBTI: 선택
- 성별·참가 구분: 기존 확정 항목 선택
- 인원: 선택
- 거주지역: 검색·선택
- 참가 날짜: 선택
- 도착 예정시간: 기존 옵션 선택 또는 시간 선택
- 프로필 관심사·성향: 선택형 버튼
- 지인 추가: [+ 지인 추가]
- 사진: [사진 선택]
- 필요한 동의: 명확한 체크박스

닉네임·자유 문의·예외적인 주소처럼 직접 입력이 꼭 필요한 항목만 입력칸을 유지해.

선택 후에는 즉시 선택 상태를 보여주고, 서버에 저장되는 항목은 성공 확인 후 완료로 표시해.

## 7. 동반신청 최종 연결

현재 진행 중인 동반신청 개발을 확인하고 이어서 완성해.

최신 확정 정책은 다음과 같다.

- 본인과 친구는 사람별 정보·순번·회비가 각각 존재
- 함께 신청하는 순간 사람별 참가 상태와 회비를 확정
- 합산 입금 가능
- 운영자는 각 사람별로 승인
- 본인과 친구의 프로필·혜택·입장·행사카드·기록 분리

대표자가 신청했다고 친구의 개인정보·기존 계정 권한을 자동으로 갖게 해서는 안 된다.

기존에 완료된 친구 카드와 복구 기능은 재사용하고, 남은 확정·승인 연결만 보완해.

## 8. 공지사항을 운영자가 직접 만들게 해

기존의 길고 중복된 기본 안내문 중심 구조를 변경해.

앞으로 공지는 내가 직접 작성하거나 사진을 올리는 방식으로 운영하고 싶어.

관리자 공지 작성 화면에 다음 기능을 제공해.

[글 작성] [사진 업로드]
[미리보기] [저장]

필요하면 여러 장 업로드·순서 변경·교체·연결 해제가 가능해야 한다.

PC 파일 선택과 휴대폰 갤러리 업로드를 모두 지원해.

기존에 화면에 자동으로 반복되는 공지와 샘플 설명은 기본 노출에서 제외해.

다만 기존 공지의 역사·확인기록·사용자 동의 기록까지 영구 삭제하지 마.

사용자 작성 공지와 업로드 이미지가 실제 화면에 표시되고, 새로고침 후에도 유지되도록 해.

필수 법적 고지·참가조건은 별도로 보존해.

## 9. 지도도 직접 올리고 관리하게 해

공지와 마찬가지로 관리자에서 지도 이미지 또는 확정 장소 자료를 직접 등록할 수 있게 해.

[지도 사진 업로드] [장소 안내 작성]
[미리보기] [교체] [저장]

기존 자료 선택 기능이 있다면 재사용해.

장소를 추측하거나 잘못된 주소로 자동 등록하지 마.

승인 전 이용자에게는 공개 가능한 범위만 보여주고, 자세한 장소·주소·지도는 기존 승인 권한 정책에 맞춰 공개해.

원본 이미지·권한·기존 주소는 보존해.

## 10. 술번개방과 전국투어 표시 구분

현재 전국투어인데 화면에 ‘술번개방’ 같은 이름이 나오거나, 지역과 어울리지 않는 기본 이미지가 나오는 부분을 수정해.

행사 종류에 따라 올바르게 표시해.

- 전국투어 → 전국투어 행사명과 지역
- 일반 술번개 → 술번개 행사명
- 할로윈·기타 이벤트 → 해당 이벤트명

기존 행사 ID나 과거 참가 기록은 변경하지 말고 표시명만 올바르게 연결해.

기존에 전달한 전국투어 5개 지역과 매장 로고 9종을 재사용해.

## 11. 술번개방 만들 때 포스터 업로드

관리자가 행사·술번개방을 생성하거나 수정할 때 포스터와 대표 이미지를 설정할 수 있게 해.

[포스터 업로드] [기존 이미지 선택]
[대표 이미지 지정] [미리보기]

이벤트마다 다른 포스터를 사용할 수 있어야 한다.

행사 목록의 썸네일, 행사 상세 상단, 관련 대기방 등에서는 같은 행사에 연결된 포스터와 로고를 일관되게 사용해.

이미지가 없으면 깔끔한 기본 카드로 표시하되, 엉뚱한 매장 로고나 잘못된 행사 이미지를 임의 연결하지 마.

이미 사용 가능한 EventMedia·MediaManager·VenueLogos 등 업로드와 자산 관리 기능이 있다면 재사용해.

기존 파일 영구삭제 없이 교체·연결해제·복원이 가능해야 한다.

## 13. 웹 속도 최적화 — 이번 최우선 과제

지금 실제 웹의 로딩과 저장이 너무 느리다.

특히 저장 버튼을 눌렀을 때 ‘저장 중’이라는 표시가 잘 보이지 않고, 처리가 멈춘 것처럼 느껴진다.

기존 동작을 기준으로 원인부터 측정해.

**반드시 점검할 것**
- 최초 화면 로딩과 재접속 속도
- 신청 단계 이동 속도
- 프로필 저장 속도
- 신청·입금 신고 저장 속도
- 이미지·포스터 업로드 속도
- 대기방 상태 갱신 속도
- 하트·채팅 응답 속도
- 불필요한 API 중복 호출
- 과도한 상태 조회·폴링
- 불필요한 재렌더링
- 대용량 이미지 다운로드
- DB 조회·쓰기 지연

**저장 UX 개선**
- 누르는 즉시 버튼에 눈에 띄는 ‘저장 중…’ 표시
- 처리 중 중복 클릭 방지
- 저장 성공 시 명확한 완료 표시
- 실패 시 입력값 보존과 다시 시도
- 네트워크가 느리면 ‘연결 확인 중’ 등 정확한 상태 표시
- 단순 로딩 장식 때문에 전체 화면이 멈추지 않게
- 실제 저장 성공 전에 ‘완료’ 표시 금지

화면 반응은 가능하면 즉시 체감되게 하고, 일반적인 저장 작업은 P95 2초 이내를 목표로 최적화해.

단, 실제 지연이 있다면 원인을 숨기지 말고 측정값을 보고해.

이미지 최적화, 지연 로딩, 캐시, 요청 중복 제거, 상태 관리 개선 등을 사용하되 정상 기능과 실시간 동기화를 깨뜨리지 마.

150명 집중 접속 시나리오도 기존 격리 테스트로 재검사해.

## 14. 모바일·PC 최종 검사

휴대폰 320·390·430px,
태블릿 768·1024px,
PC 1280·1440px를 확인해.

긴 설명·큰 흰색 박스·버튼 겹침·가로스크롤·로딩 표시 가림이 없어야 해.

실제 화면으로 다음 흐름을 끝까지 확인해.

신청하기
→ 혼자/지인 선택
→ 년생·지역 선택
→ 공지 확인
→ 회비 확인
→ 저장
→ 신청대기방
→ 프로필
→ 입장
→ 하트·채팅·행사카드

공지 사진 업로드·지도 업로드·행사 포스터 등록도 실제 선택·미리보기·저장·재열기까지 검사해.

가짜 성공 메시지나 합성 테스트만으로 실제 저장이 됐다고 보고하지 마.

## 15. 기존 기능·데이터 보호와 작업 완료

기존 신청·입금·프로필·하트·채팅·행사카드·상품·당첨·지급·사용자 기록은 반드시 보존해.

DB/API 변경이 꼭 필요하면 기존 구조를 재사용하고, 백업·복원 가능성·권한·호환성을 확인한 최소한의 변경만 해.

보스 전용 잠금 ON,
시험실 ON,
일반 신청 차단 상태는 유지해.

main 무단 병합·강제 Push·운영 키 교체·파괴적 데이터 변경·일반 모집 오픈 금지.

현재 배포 SHA와 최신 개발 브랜치부터 비교하고, 수정 후 자동검사와 실제 화면 검사를 모두 통과시켜.

안전하게 검증된 변경만 기존 보스 전용 테스트 환경에 반영하고, 일반인에게 공개하지 마. 기존 승인 범위 밖의 배포나 권한 변경은 하지 마.

최종 보고는 다음 항목만 명확히 해.

1. 수정 완료 기능

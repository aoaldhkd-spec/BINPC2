# 운영 배포 승인과 현재 실행 조건

2026-10-28 KST 최신 사용자가 “지금 일단 운영배포해볼래?”라고 요청했다. **기존 사이트 운영 배포 승인은 받았다.** 과거 문서의 ‘배포 승인이 아직 없다’는 설명은 이 승인 범위에서는 과거 상태다. 개인정보 정책 확정, 실제 모집 공개, 외부 발송, 키 교체, 운영 데이터 삭제 승인은 별개이며 받지 않았다.

현재 Netlify/Render 접속은 이 실행 환경의 네트워크 경유 계층에서 `Tunnel connection failed: 403 Forbidden`으로 막힌다. 기본 실행과 허용된 확장 권한의 읽기 전용 재확인에서 동일했다. 운영 사이트 자체가 고장 났거나 계정 비밀번호가 틀렸다는 증거가 아니다. Netlify/Render 관리 API 연결·환경 토큰·기존 표준 CLI 인증 파일·프로젝트 배포 인증 파일도 이 환경에 없다. 다른 사용자의 계정을 추측하거나 과거 폐기된 자격증명을 재사용하지 않는다.

Netlify Stopped builds / Render main 자동배포는 사용자의 기존 확인이다. 이 상태에서 main만 먼저 바꾸면 API만 올라가고 화면은 그대로일 수 있다. 운영 DB 스키마·암호화키·백업·현재 배포 버전도 아직 독립 확인하지 못했다. 이 조건을 무시한 불완전한 배포는 실행하지 않는다. 운영 main을 강제로 되돌리지 않는다.

PC방 Chrome에서 기존 `https://binpc2.netlify.app`를 이용하는 데 별도 프로그램 설치는 필요 없다. PC방의 공식 Netlify/Render 웹 로그인은 사용자가 직접 할 수 있으나 이 Codex 세션으로 공유되지 않는다. 비밀번호·인증키를 채팅에 보낼 필요가 없다. 기존 프로젝트의 관리 접근이 가능한 배포 환경이 연결되거나, 운영자가 공식 웹 화면에서 배포를 실행하고 상태를 확인해야 실제 반영을 완료할 수 있다. 새 서버·새 DB·유료 서비스·공개 터널은 필요하지 않다.

전체 할로윈: 최신 사용자 지시에 따라 메인·신청·대기방·문의·프로필·하트·채팅·관리자 전체에 적용한다. 기존 DB헬스 `seasonal_landing` 스위치를 **전체 할로윈 테마**로 재사용하며 OFF 시 기존 디자인/다크모드 취향으로 복원한다. 2026-11-01 17:00 KST 전체 장식 만료는 개별 행사 입장·뽑기·17시 초기화와 분리한다. 최신 테스트 모드와 연결 재검사는 [최신 통합 보고서](LATEST_TEST_MODE_AND_DEPLOYMENT_2026-10-28.md)를 우선한다.

개인정보 승인안: [쉬운 표와 고지 원문](PRIVACY_POLICY_APPROVAL_DRAFT_2026-10-28.md). 운영 반영의 백업·스키마·OFF 적용·복구 순서는 [기존 반영 준비서](EVENT_HUB_V6_EXISTING_SITE_ROLLOUT_2026-10-27.md)를 그대로 사용하되, 사용자의 이번 배포 승인 사실을 우선한다.

## 403 원인과 해소에 필요한 실제 설정

환경 설정 조회 결과 인터넷은 `restricted`이며 사용자 정의 허용 목록에는 `api.github.com`, `api.netlify.com`, `api.render.com`만 있었다. 운영 화면/상태 확인에 필요한 `binpc2.netlify.app`, `binpc2.onrender.com`이 빠져 있었다. 관리 API 호스트가 저장된 초안에 있다는 것과 실행 환경에서 이미 허용됐다는 것은 다르다. 실제 호출은 여전히 경유 계층의 403이며, 인증 요구 목록도 비어 있었다.

기존 목록과 패키지 다운로드 프리셋을 보존하고 운영 주소 두 곳을 추가했다. `NETLIFY_AUTH_TOKEN`은 `api.netlify.com`에만, `RENDER_API_KEY`는 `api.render.com`에만 보내도록 개인 보안 인증 입력 요구를 추가했다. 값·비밀번호·실제 운영 Secret은 읽거나 저장하지 않았다. 설정 도구는 `status:saved`, `requires_publish:true`를 반환했다. 초안 저장은 실제 네트워크 적용·인증 완료·운영 배포가 아니다.

사용자가 할 일은 **Codex 환경 설정에서 이번 변경을 검토·저장하고 환경을 게시(Publish)**하는 것이다. Netlify/Render 관리를 Codex가 실행하려면 같은 설정의 보안 인증칸에 해당 계정의 인증값을 등록해야 한다. 공식 Netlify/Render 웹에 본인이 로그인해 인증을 관리하며, 채팅으로 값을 보내지 않는다. 기존 운영 앱의 비밀번호·암호화키를 바꾸는 작업은 필요 없다. Codex 환경 게시가 운영 사이트 배포를 실행하지는 않는다.

현재 이 환경에는 사용자의 Chrome 로그인 세션을 공유받거나 대신 로그인할 브라우저 연결이 없다. PC방에서 로그인해도 해당 세션이 자동 연결되지는 않는다. 지원되는 관리 인증과 네트워크 적용을 확인한 다음 기존 사이트·DB 준비 상태부터 읽고, 승인된 운영 배포를 진행한다. 연결 전 main만 밀어 API와 화면을 서로 다른 버전으로 만들지 않는다.

개인정보 책임 주체 **범일NPC**, 문의처 **기존 관리자 1:1 문의**는 사용자 답변으로 확정했다. 보관기간 전체는 여전히 검토안이며 모집·자동 삭제를 켜지 않았다.

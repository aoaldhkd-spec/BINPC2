## 변경한 동작

- **일반 방문자 잠금은 유지**하고, 서버가 확인한 보스 로그인에서는 메인의 술번개 신청·입장 버튼을 사용할 수 있다. 새로운 HTML/사이트/별도 참가자 화면은 만들지 않았다.
- `/events`의 **금요일·토요일 신청 열기 / 이어하기**는 기존 React 신청 화면과 같은 API·DB 흐름을 사용한다. 서버가 표시한 보스 확인용 회차만 접수 시간/공개 잠금 예외를 적용한다. 실제 행사 설정·신청 순위·재고·회식 주기를 변경하지 않는다. 기존 시험실의 workspace도 초기화하지 않는다.
- 실제 기본정보 저장→동의→신청 확정→관리자 가상 승인→필수 프로필→입장→같은 프로필 재접속을 사용한다. 관리자 권한이 일반 참가자 DB 요청/SSE에 자동 첨부되지 않는다. 로그인은 그대로 보존된다.
- 시험 참가자의 기존 운영 참가자 대상 하트·메시지·프로필 방문기록을 서버에서 차단한다. 시험 프로필과 운영 프로필 목록·자동 단체방을 분리하고, 시험 프로필 SSE는 같은 시험행사 참가자/관리자에게만 전달한다. 이 표시는 일반 프로필 수정으로 바꿀 수 없다. 승인 취소·본인/회차 확인은 유지한다.
- 친구별 초안/초대/본인 수락을 추가했다. 대표자의 프로필과 친구의 계정·하트·채팅 권한은 분리한다. 친구가 본인 세션에서 수락하고 기존 신청 절차를 마쳐야 순위/신청이 생긴다. 초대는 만료·단회 사용·해시 저장하며 요청 이력에 원문 초대를 저장하지 않는다.
- 기존 로고 9종/업로드 이력을 재사용해 순서 변경·연결 해제·기본 연결 복원을 추가했다. 명시적 빈 목록은 자동 기본 로고로 되돌아가지 않는다. 주소 연결 해제도 이전 이력을 보존한다.
- 계좌 선택 후 확정 전에 계좌가 바뀌면 다시 선택하도록 안내한다. 이미 확정된 입금 안내/신고/승인은 소급 변경하지 않는다. 실제 계좌를 시험행사/공개 소스에 넣지 않는다.
- 재시작 시 기본 대화방 4개를 DB에서 읽기 전에 빈 메모리에서 새로 만들던 순서를 수정했다. 기존 방·참가·메시지를 먼저 읽고 누락 방만 만든다. 과거 생성시각은 추측해 복원하지 않았다.
- 입장 프로필/기기/신호 저장을 같은 트랜잭션의 한 쿼리로 묶었다. 신청 조회는 인덱스 분기와 필요한 시점의 복호화로 변경했다. 잠금·재고·중복 방지는 유지한다.

## 직접 눌러볼 순서

수정본 반영 확인 후 기존 https://binpc2.netlify.app/ 에서:

1. **운영자 로그인** → 기존 인증. 이미 로그인했다면 그대로 진행.
2. **술번개 신청**(또는 상단 **일반 화면에서 신청·입장**).
3. **금요일·토요일 신청 열기 / 이어하기** → 원하는 금/토 회차 → **신청하기**.
4. 본인 기본정보·동의·신청 확정. 친구는 **친구와 함께 신청 · 본인/친구 따로 관리**에서 따로 저장한다. 실제 송금은 하지 않는다.
5. 상단 **관리자 → 🎉 술번개**에서 해당 보스 확인용 신청을 무료 승인 또는 가상 입금 승인.
6. 일반 화면의 **신청대기방**으로 돌아와 필수 프로필을 완료 → **술번개 입장하기**. 기존 참여자·하트·채팅 메뉴를 확인하고 새로고침해 같은 프로필을 확인한다.
7. 시간 변경/가상 3등·뽑기는 기존 **행사 설정·기록·관리 도구 → 선착순 시험실**에서 계속 시험한다. 기존 사용자 시험 기록을 임의 초기화하지 않는다.

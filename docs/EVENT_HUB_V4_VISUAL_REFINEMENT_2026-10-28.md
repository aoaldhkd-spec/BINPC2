## 모바일 프로필 첫 화면 복귀

이번 변경은 기존 복구·권한·17시 초기화 보호를 유지했다. 실제 React/API/격리 DB에서 저장 실패 후 입력 유지, 새 브라우저 복구, 승인 후 동일 신청 복구, 프로필 완성 후 입장, 하트·채팅 상태 검사를 다시 수행했다. 이전 부분 응답·역순 응답·저장소 오류 보호 코드를 제거하지 않았다.

물리 갤럭시·아이폰, 실제 은행·카카오톡 앱 전환, 잠금/해제는 **UNKNOWN**이다. 운영에 배포하지 않았으므로 운영 휴대폰 문제가 해결됐다고 판정하지 않는다. 운영 반영 후 기존 주소에서 같은 행사 주기 안에 프로필/고유번호/하트/채팅/입금 상태를 기록하고 앱 전환→잠금→복귀→새로고침 순서로 확인해야 한다. 정상 17시 초기화 후 끝난 현장 프로필을 무단 복구하면 안 된다.

## 성능·보관·보안 범위

- 이번 첫 빌드 기준 전체 정적 파일 8,232,293바이트: 이전 V4 8,041,862바이트보다 190,431바이트(약 2.37%) 증가. 장식 이미지가 169,690바이트다. 용량이 줄었다고 보고하지 않는다. 최종 메모 보호 보완 빌드 전체는 8,232,472바이트다.
- 사용자 목록은 6개씩, 관리자 신청자 목록은 10개씩 표시하고 선택한 상세 양식 하나만 렌더링한다. 기존에는 누적 신청자의 상세 양식을 전부 렌더링했다. 표시만 줄이며 기록은 보존한다.
- 운영 인터넷·실기기 로딩 속도 개선율은 측정하지 않았다. 앞선 V4 실제 응답시간·150명 검사·15분 장시간 검사 증거를 보존한다. 이번 변경은 새로운 15분 장시간 시험 성적을 만들지 않는다.
- 소스·원본 로고·실패 증거·Git 이력·백업·키를 삭제하지 않았다. 독립 HTML, 외부 시험 사이트, 유료 서비스, 공개 터널을 만들지 않았다.
- 현재 추적 파일·새 파일·ZIP 내용에서 비밀키 패턴, 개인 시험 비밀값, DB 덤프를 검사했다. 화면에는 합성 기록만 사용했다. 과거 Git 이력 전체를 무비밀로 인증한 것은 아니다. 이전 노출 가능 값의 유효성 확인/폐기는 기존 별도 운영 준비 항목이다.
- Netlify Stopped builds 및 Render main 추적은 앞서 사용자가 확인한 설정을 기준으로 한다. 연결 서비스 계정 설정을 이번 도구가 새로 읽어 검증한 것은 아니다. 배포 설정 파일을 변경하지 않았고, feature 브랜치만 push했다. PR·main 병합·운영 배포 없음.

## 직접 확인하는 순서와 운영 전 잔여 항목

1. 기존 BINPC2에 승인된 코드가 반영된 뒤 메인에서 **술번개 신청**을 누른다.
2. 금/토 행사를 선택해 공지를 보고 기본정보·필수 동의를 저장한다. 다음 단계에서 회비를 확인한다.
3. **신청대기방**에서 같은 신청과 승인 상태를 확인한다. 프로필을 작성하고, 미완성 상태에서는 입장이 차단되는지 확인한다.
4. 관리자는 기존 대시보드 **술번개 → 금/토 → 신청·입금**에서 참가자를 검색해 선택한 뒤 실제 은행 내역을 직접 대조한다.
5. **공지·장소**에서 공개 공지와 승인 후 지도를 각각 등록한다. **현장·상품**에서 금·토 재고와 선택한 참가자의 지급 결과를 확인한다.

이번 화면은 실제 내부 앱에서 검사했으며 현재 운영 주소에 반영되어 있지 않다. 새 외부 테스트 주소도 발급하지 않았다. 운영 반영 전 최종 승인이 필요하다. 개인정보 목적별 보관·삭제·백업 기간 확정, 실제 운영 DB·업로드·암호화키 백업/복구 확인, 실기기 확인은 별개다. 코드 ZIP/Git bundle을 운영 DB 복구 완료로 표시하지 않는다. 개인정보 정책 미확정 production 신규 접수 차단은 그대로다.

최신 화면을 사용자가 직접 확인하기 전에는 전체 UI가 최종 승인됐다고 판정하지 않는다. 기존 V6·할로윈·투어의 기능별 상태와 나머지 운영 준비는 기존 통합 체크리스트/인계서를 유지한다.

## 화면에서 바뀐 점과 사용 순서

[실제 전후 화면 모음과 짧은 앱 녹화](reviews/v4-ui-20261028/README.md)를 먼저 보면 된다. 새 앱을 만든 것이 아니라 기존 BINPC2의 부품·관리자 탭·저장 API를 재사용했다.

1. 메인 가운데 **술번개 신청 / 신청대기방**을 누른다. 두 버튼 바로 아래가 **입장하기**다. 신규 입장은 서버가 실제 회식 시작을 알리기 전에는 열리지 않는다.
2. 신청에서는 날짜 → 기본정보 → 개인정보/공지 동의 → 회비 → 입금 신고 순서다. `저장 중…` 다음 서버 저장 확인 후 이동한다. 이미 작성한 신청은 신청대기방에서 이어간다. 신고는 입금 승인과 다르다.
3. 관리자에게 묻고 싶으면 **신청 화면 오른쪽 아래 관리자 문의**를 누른다. 메인·일반 하트/채팅·관리자 페이지에는 이 문의 버튼을 중복 표시하지 않는다. 프로필 작성 단계에서도 사용할 수 있다.
4. 관리자는 기존 대시보드의 **술번개 → 전체 / 금요일 / 토요일**을 고른다. **신청·입금 / 공지·장소 / 관리자 문의 / 현장·상품**에서 처리한다. 고급 행사 설정·개인정보·검사·가상 시험실은 접힌 관리 도구 안에 남겨 두었다. 일반 처리에 시험실을 거칠 필요가 없다.
5. **공지·장소**에서 파일을 선택하고 미리본 뒤 저장한다. 공지 사진만 명시적으로 신청 전 공개한다. 지도·상세 주소·대기방 사진은 입금 확인 또는 무료 참가 승인 후 해당 신청자에게만 보인다. 운영용 실제 계좌/장소를 공개 공지 사진에 넣지 않는다.
6. **현장·상품 → 전체**에서 금요일23개·토요일49개를 함께 본다. 각 품목의 배정·당첨·지급·미지급·잔량은 기존 원장에서 읽는다. 날짜 전환으로 상품을 복제하거나 보충하지 않는다.

## 시작·종료와 복구

- 집 PC 검토판은 준비 도구의 `activate`가 가상 회식을 시작해 둔 상태였음이 첨부 기록에 있다. 운영이 항상 열려 있다는 증거는 아니다. 내부 시험은 명시적으로 시작 전/후를 전환하여 확인하고 운영 세션에는 요청하지 않았다. 검사 종료 때 내부 V4 회식을 시작 전(false)으로 돌렸으며 행사26/신청648/재고25/문의7개가 그대로임을 확인했다. 이는 집 PC나 운영 세션을 변경한 것이 아니다.
- 시작 상태가 `null`일 때도 신규 입장을 막도록 입장 게이트를 보완했다. 기존 `admin_toggle_session`/서버 검사는 유지한다. 20시 신청 접수와 현장 회식 시작은 다른 상태다.
- 할로윈 금22:30·토22:00 시작, 양일 익일01:00 신규입장 마감. 정상 기존 참가자 복귀는 같은 행사 cycle/본인인증을 확인한다. 해당 회차 테마·기존 카드 사용은 익일17:00까지이며, 다른 방을 끄거나 원장을 지우지 않는다. 전국투어 차수별 시간은 변경하지 않았다.
- 첫 화면의 입장 전 체크 카드·하트 시간 배너·모임 시작 배지만 제거했다. 하트23시/무지개24시·01시/17시·동의·PIN·하트/채팅 기능과 검사는 남아 있다.

## 모바일 프로필 복귀 오류: 원인과 검증 상태

**운영 갤럭시·아이폰의 단일 원인은 아직 확인하지 못했다.** 운영 배포 SHA/실물 휴대폰 로그를 확보하지 못했으므로 실기기 해결 완료가 아니다.

V6에서 부분/빈 응답과503, 역순 응답, 과거 초기화 신호, 저장소 예외를 미가입으로 취급할 위험 경로를 고쳤고 이번에도 회귀검사를 유지했다. 실제 Chromium+API+PG에서 같은 프로필·닉네임·고유번호·하트/채팅 기록·신청/입금 승인을 새로고침·단절/재연결·앱 복귀 신호 뒤 확인한다. 작성 중 프로필도 보호한다. 진짜17시 만료는 복원하지 않으며 별도 신청/입금/당첨 원장은 보존한다. V4는 조회가 미확정일 때 입장 버튼이 열리지 않도록 추가 보완했다.

실물 최종 순서: 정상 등록/승인과 프로필·PIN·하트·채팅을 확인 → 잠금/해제 → 은행·카카오톡 이동 후 복귀 → 새로고침/탭 재열기 → 비행기모드 후 재연결 → 같은 항목 확인. 문의 입력 중 키보드와 저장/닫기 버튼도 확인한다. 이 단계는 배포 승인 후 기존 주소에서 관리자 통제하에 진행한다.

## 사진·문의의 실제 검증

공지/지도 파일 선택→원본 비율 미리보기→실제 서버 저장→다시열기→승인 전/후 참가자 표시를 검사했다. 지도는 승인 전 상태 JSON에서 URL 자체를 제외하고 원본 HTTP도 차단한다. 타 행사/타 신청자의 승인으로 열리지 않으며, 기존 비공개 파일을 공지로 일괄 전환하지 않는다.

여러 파일, 설명, 순서, 확대, 연결 해제/복원과 원본 보존을 확인했다. 사진을 먼저 올린 뒤 공지/장소를 저장해도 media revision이 사라지지 않는다. 다른 관리자가 같은 필드를 바꿨으면 입력을 남기고 충돌을 알린다. 새 행사 업로드 실패 후 같은 행사로 재시도한다. 사진 형식·2MiB/영상5MiB·권한 검사, 활성10개/보존40개 한도는 유지한다. HEIC는 지원하지 않는다. 미리보기 조회 실패도 무한 로딩 대신 원본 보존 안내와 다시 불러오기를 제공한다.

문의는 같은 신청 컨트롤러와 SSE를 공유하도록 바꿨다. 전역 문의 컨트롤러·15초 중복 폴링을 제거했다. 오른쪽 아래 버튼, 뒤로가기/다시열기 초안 보존, 관리자 답장, 짧은 화면의 보내기 버튼 영역을 확인했다. 실제 iOS/갤럭시 키보드와 OS 잠금 복귀는 UNKNOWN이다.

## 안전 저장·정리·백업

전체 정적 빌드 파일은 이전8,025,151B에서 최종8041862B로 늘었다. 관리자 사진 편집 기능 추가분이 있으며 전체 앱 용량 감소라고 주장하지 않는다. 메인 초기 전송량의 감소와 디스크 임시파일 정리는 별개다.

재생성 가능한 이전 번들 복사본 `.local/v4-work/baseline-public` 8,025,151B만 정리했다. 전후 캡처·해시 목록·기존 소스·정본·원본 로고8종·DB/키/업로드·Git/실패 이력은 보존한다. 새 검토 ZIP/녹화는 docs에 있으며 앱 public 자산이나 첫 화면 다운로드에 포함되지 않는다.

공개 저장 검사는 현재 파일/ZIP 구성원·알려진 비공개 시험 키·토큰·덤프 서명을 검사했다. 추가 점검에서 과거 복구 스크립트의 고정 로그인 후보와 운영자 연락처를 발견하여 현재 코드에서 제거했다. 시험은 합성 연락처로 통일하고 운영 스크립트는 기존 명시적 대상/확인 보호를 재사용했다. 실제 비밀번호/Secret/DB를 변경하거나 해당 스크립트를 운영에 실행하지 않았다.

정적 감사는 오류0/경고93이며 대부분 합성 시험/생성물·규칙의 후보 경고다. 수동 추가점검의 P1 고정 로그인 후보/실행 보호 누락과 P2 연락처를 별도로 수정했다. 과거79/92/94건 성적은 역사로 보존하고, 경고 숫자가0이라는 식으로 보고하지 않는다. [중요도 분류](reviews/v4-ui-20261028/verification/audit-classification.json).

**과거 Git 이력은 재작성하지 않았다.** 과거 공개된 값의 현재 유효성은 확인하지 않았으며, 완전 무유출 또는 모든 과거 비밀값 폐기를 보장하지 않는다. 이미 공개된 관리자 비밀번호의 폐기 여부는 운영 반영 전에 확인해야 한다. `SESSION_SECRET`은 암호화 기록과 관련되므로 단순 교체하지 않는다. 현재 원문 소스 ZIP과 비공개 Git bundle은 코드 복구 자료이고 운영 DB·업로드·암호화키 백업/복원 완료 증거가 아니다.

## 기존 사이트 반영 전 남은 항목

- 개인정보 목적별 기간·철회/삭제 예외·백업 보존/복구 책임자 확정. 초안 보호를 삭제하지 않는다. 자동 파기는 미실행이며 production 신규 접수 차단 유지.
- 운영 DB·업로드와 일치하는 키의 보호된 백업, 격리 복구 시험, 기존 schema/lookup metadata 적용 순서 확인. [기존 반영 준비서](EVENT_HUB_V6_EXISTING_SITE_ROLLOUT_2026-10-27.md)를 따른다. 새 모듈은 우선OFF로 반영 후 관리자 확인 뒤 필요한 것만ON.
- 실제 Render/Netlify 배포 버전과 운영 성능, 실제 Galaxy/iPhone 키보드·절전·앱 전환·푸시/알림 확인. 외부 영상은 직접 확인한 증거가 없으며 보았다고 주장하지 않는다.
- main 병합·배포·서비스 설정/Secret 변경·실제 모집·외부 발송·운영 개인정보 삭제는 별도 승인. 현재 요청은 준비까지이며 이 항목들은 실행하지 않았다.

운영 사이트를 열었을 때 아직 예전 화면이 보이는 것은 이 개발 브랜치를 배포하지 않았기 때문이다. 새 외부 주소를 만들지 않았으며, 집 PC의 기존 검토 폴더를 원격에서 갱신했다고 주장하지 않는다. Cursor는 최신 브랜치/인계 문서부터 이어가며 독립 HTML을 다시 만들지 않는다.

## 3. 비공개 실앱 시험 환경

**참가자 외부 주소: 아직 없음. 관리자 외부 주소: 아직 없음.**
localhost·캡처·영상·정적 HTML을 외부 실앱 프리뷰라고 안내하지 않는다.
Codex 포트 공개를 반복 시도하지 않았다.

준비한 실제 배포 구성: [deploy/private-preview](../deploy/private-preview/README.md).

- 별도 Render native Node 웹1개 + 별도 PostgreSQL1개, 같은 HTTPS origin의 React/Express.
- autoDeploy OFF, 검증된 PREVIEW_SOURCE_SHA와 실제 checkout SHA 일치 필수. 개발 브랜치가 움직여도 시험판을 자동 갱신하지 않음.
- 전체 UI/정적 파일/API 접근 로그인 + 별도 관리자 인증. localhost용 Vite 관리자 자동로그인을 외부에 배포하지 않음.
- NODE_ENV=production의 보안 유지. APP_MODE=private-preview, 전용DB 이름/호스트·독립 secret·외부 발송 키 부재를 모두 확인해야 합성 시험 흐름만 허용.
- 일반 운영 production의 미확정 개인정보 신규 접수 차단은 그대로다. 개발 모드로 바꿔 우회하지 않음.
- DB명 binpc2_private_v6, 실제 시험에서 운영 DB/계정/키/신청 자료를 복사하지 않음.
- 기존 Express의 정적 앱 경로 불일치도 수정해 한 주소에서 실제 React 파일을 제공.
- 일반 PostgreSQL에 Supabase anon/authenticated 역할이 없더라도 RLS/권한 회수가 실패하지 않도록 보완.
- 외부 발송 차단, 운영 API/SSE 주소를 빌드에 연결하지 않음, noindex/no-store.
- 전용 로컬 production-mode 실앱에서 인증 없는 참가자/관리자/API401, 접근 로그인만으로 관리자API403 등 HTTP10개 통과.
- Docker 대안 전체 빌드는 컨테이너의 npm DNS EAI_AGAIN으로 실패했다. 패키지 보호를 끄지 않았고 native Node 배포를 기본안으로 준비했다.

비용은 기존 공개 가격 기준 웹7+DB6=약 US$13/월 **예상**이다. 공식 요금 페이지가403이어서 현행 요금/세금/추가 사용료는 미확정이다.
승인한 예산과 실제 계정 가격 확인 전 자원을 만들지 않는다. 현재 외부 서비스 생성/배포/과금0(로컬 격리 DB만 생성).
Render 관리 연결이 없으며 GitHub secret 메타데이터 조회도 integration 권한403이었다. 비밀값 추출·우회는 시도하지 않는다.
승인/계정 연결을 받으면 검증 SHA로 별도 서비스만 배포하고 실제 HTTPS·권한·같은 DB·외부 발송 차단을 다시 확인한 뒤 주소를 제공한다.

## 4. 직접 시험할 순서

주소가 실제 발급된 뒤 PC방 Chrome 시크릿창 또는 Galaxy/iPhone에서 같은 시험 주소를 연다.
접근 계정과 관리자 계정은 다르며 비밀번호는 GitHub/ZIP에 넣지 않고 비공개 전달한다.

1. 가상 행사·가상 닉네임·가상 전화번호로 신청하고 서버 저장 완료를 확인.
2. 관리자 별도 로그인 → 같은 신청 수동 입금/무료 승인 → 참가자 장소·대기방 갱신 확인. 실제 송금 안 함.
3. 일부 프로필 작성→뒤로/새로고침→복원, 완료→현장 입장→닉네임/PIN 확인.
4. 하트·채팅 사용 후 잠금/해제→은행·카카오톡 이동/복귀→새로고침→비행기 모드/복구 순서로 동일 프로필/횟수/대화 확인.
5. 늦참 종료 이후 신고→관리자 검토→납부 유도 차단과 기존 입금 승인 보존 확인.
6. 기록 전화번호 저장→관리자 결과/금액/실물 지급 기록 대조. 전화번호만으로 타인 기록을 열 수 없는지 확인.
7. 독립 시험실에서 가상3등·접수 직전/정각·17시 전후·중복/응답 유실을 선택. 운영 시계·재고는 건드리지 않음.

현재는 외부 주소가 없으므로 사용자에게 내부 경로나 수동 설치/명령을 실행하라고 요구하지 않는다.

## 5. 검사·실패·성능·자료 보존

기존1306/57/6과 efd409ba 및 이전 GitHub Actions 성공 이력을 유지한다.
최신 숫자는 아래 최종 갱신/동봉 validation.json에 기록한다. 실패 로그도 보존한다.

- 실제 격리 PostgreSQL: 예약2일 정각·중복/재시작/수동중지, 소유권/동일번호 비병합, 수동 결과·중복 지급,01시 session_active=false에서도 기존 복구/잔여 카드,17시 만료/원장 보존, RLS 역할 호환을 추가했다.
- 최신 전체 브라우저 중간 실행11개는9통과/2실패였다. 사진 검사1건은 이전 시험방00:30 설정을 V3의01시로 보통 관리자 저장 후 단독 통과했다.
- 개인정보 검토는 저장 요청 응답 시작33ms·재조회 응답 시작231ms였으나 누적 회원 전체 렌더 화면에서 기존5초 상태 검사가 반복 실패했다. 관리자 회원 목록을 검색·50명 표시로 제한한 뒤 같은5초 검사가 통과(검토 응답 시작22ms·재조회 응답 시작209ms). 기록/기능/검사를 삭제하지 않았다.

## UI 작업 위치

경로 기준은 `artifacts/boltnew-app/`이다.

| 화면 | 주요 파일 |
|---|---|
| 메인 이름·신청/대기방/입장·복구·관리자 톱니바퀴 | `src/components/WaitingOverlay.tsx`, `WaitingOverlay.css` |
| 할로윈 표시 | `src/themes/halloween.css`, `SeasonalSkin.tsx`, `public/event-art/` |
| 신청·대기방·입력 단계 | `src/event-hub/EventHubPage.tsx`, `EventPresentation.tsx`, `HubUi.tsx` |
| 공지·친구·로고 | `src/event-hub/NoticePages.tsx`, `CompanionCards.tsx`, `VenueLogos.tsx` |

표시명은 **범일NPC 술번개**, 주소는 유지한다. 상단 보스 안내 3줄과 입장 아래 설명은 제거된 상태다. 관리자는 우측 톱니바퀴, 로그아웃은 기존 관리자 화면이다. 주황/짙은 보라/크림색 버튼과 강화한 할로윈 배경을 바탕으로 조정한다. 기존 인터랙션을 재사용하며 새 HTML/새 관리자 사이트를 만들지 않는다.

레이아웃·간격·색상·가독성·반응형·표시 문구 위주로 수정한다. 프로필·긴 공지·글자 확대·키보드에는 자연 스크롤을 허용한다. `overflow:hidden`으로 필수 버튼/내용을 잘라내지 않는다. 이미지·폰트·상태 조회 완료 화면과 느린 로딩 상태를 모두 확인한다. URL·저장키·행사 ID·서버 공지 원문·동의 버전은 표시명과 함께 바꾸지 않는다.

## 반드시 유지할 보호와 기능

- **보스 잠금 ON / 시험실 ON / `publicAdmissionOpen=false`.** 오픈 승인은 없다. 테스트 OFF·재시작·테마 만료·예약시각만으로 공개하지 않는다.
- 이번 읽기 확인: 보스 잠금 `locked=true`, 비로그인 신청 API HTTP423. 시험실 ON·신청 차단은 직전 실제 관리자 검증 값이며 이번 인계에서 설정을 변경하지 않았다.
- `BossAccessBoundary.tsx`의 서버 인증·SSE 권한·조회 실패 보호를 유지한다. 설명을 숨기는 것과 접근 제한을 제거하는 것은 별개다. 보스 예외는 서버가 확인한 상태만 사용한다.
- `src/lib/public-test-mode.ts`의 일반 공개 조건은 명시적 `enabled=false`와 `publicAdmissionOpen=true`다. 누락/실패한 응답을 공개로 해석하지 않는다.
- 참가자 신청·입금·승인·하트·채팅·당첨·지급·재고와 사용자가 시험 중인 기록을 삭제/초기화하지 않는다. 서버 API·승인·입장·개인정보·복구/PIN·세션 로직은 UI 범위 밖이다.
- 친구 카드의 `hidden={writing}`은 미저장 입력 보존을 위한 것이다. 조건부 언마운트로 바꾸지 않는다. `hidden={writing && !app}`을 과하게 확대하면 신청 생성 후 재사용 로그인 설정이 사라진다. 이전 CI 실패 사례를 보존한다.
- 일반 접수 차단·실제 송금 방지·필수 동의·오류 안내까지 불필요한 문구로 취급해 삭제하지 않는다. 저장 중/실패/완료, 입력 보존, 뒤로가기·재접속 복구를 유지한다.
- 테마 OFF/만료는 표시 변경이다. 업무 기능·기록을 지우거나 다른 행사를 끄지 않는다. 제공 로고 9종·원본·기존 이미지·Git 이력·테스트·복구 자료를 보존한다.
- **main 병합/push, PR 생성, Netlify/Render 배포, 운영 DB·업로드·키·비밀번호·환경설정 변경, 실제 모집·송금 유도·외부 발송 금지.** 과거 배포 승인보다 이번 일시 중단 지시가 우선한다.

## 로컬 확인과 저장

운영 `.env`·관리 토큰·실제 DB를 Cursor UI 작업에 복사하지 않는다. 기존 격리 실행기와 합성 데이터를 사용한다. `scripts/event-hub-local.mjs`는 로컬 API `127.0.0.1:8082`, 프런트 `127.0.0.1:3002`를 사용하는 기존 경로다. 이미 있는 시험 DB·키는 재생성/삭제하지 않는다. 시험환경이 준비되지 않은 PC에서는 정적 UI·단위검사부터 진행하고 운영 API에 신청/저장 요청을 보내지 않는다.

`API_PROXY_TARGET`, `API_URL`, `VITE_SSE_ORIGIN`, `DATABASE_URL`의 실제 대상을 확인한다. 별도 외부 사이트·터널·유료 서비스를 만들거나 localhost 보호를 제거하지 않는다. 새 PC의 localhost는 다른 기기에서 접속 가능한 프리뷰가 아니다.

변경은 기존 개발 브랜치에 안전하게 commit/push하되 원격이 앞섰으면 먼저 읽고 통합한다. 강제 push 금지. `.env`, `.local`, DB 덤프, 키, 실제 계좌·개인정보·인증 로그를 commit/ZIP에 넣지 않는다. 기존 로고·배경·검증 자료를 다시 제작하지 않는다.

**자동배포 주의:** 현재 Netlify는 main 추적/허용, Render도 main 자동배포다. 이번 개발 브랜치 문서 저장은 배포를 실행하지 않는다. 향후 main 업데이트가 수동 배포본을 덮을 가능성은 남아 있다. 자동배포 설정을 임의 변경하거나 main에 UI를 합치지 않는다.

## Cursor 완료 후 Codex 검증 순서

Cursor는 최종 브랜치·SHA, 미커밋 유무, 바꾼 파일/화면과 이유, 실제 검사 결과, 모바일/태블릿/PC 전후 캡처, 실패/UNKNOWN을 남긴다. 배포는 하지 않는다. 과거 CI를 새 UI 코드의 검사 결과로 보고하지 않는다.

1. 원격 최신 HEAD와 Cursor 변경을 비교하고 다른 작업자의 변경·미커밋을 보존한다.
2. UI 범위 밖의 API·권한·DB·설정 변경 및 비밀값 혼입 여부를 검토한다.
3. 관련 타입·단위·보호 검사 후 실제 격리 React/Express/DB에서 버튼·저장·뒤로가기·재열기·재접속을 확인한다.
4. 작은 화면·태블릿·PC, 테마 ON/OFF, 동의·승인·프로필·하트·채팅·문의·권한 분리를 회귀 검사한다. 원격 CI는 최종 코드 SHA와 일치해야 한다.
5. 오류 수정→재검사→증거 보존 후 결과를 보고한다. **검증 요청을 배포/모집 승인으로 해석하지 않는다.**

기존 미완료는 별도 유지: 집중 구간 2초 목표 미달, 실물 갤럭시/아이폰·백그라운드 푸시 UNKNOWN, 운영 주소/대체계좌 최종 배정, 개인정보 보관/삭제 및 친구 역참조 처리, 최신 암호화 사본 외부화, main 자동배포 덮어쓰기 위험. UI 수정만으로 완료 처리하지 않는다.

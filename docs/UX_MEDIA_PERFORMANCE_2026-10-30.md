## 3. 구현 상세와 재사용한 기능

- **신청:** 기존 단계형 신청·공지 동의·회비 산정·입금 신고·프로필·복구를 재사용했다. 새 모달과 년생·도시 선택을 연결하고 일반 전화번호 단계는 건너뛴다. 과거 작성 중인 전화번호 단계에서도 입력 내용을 지우지 않고 다음 단계로 이어진다.
- **친구:** 본인/친구의 고유 신청·순번·회비·승인·입장 권한을 분리한다. 합산 신고는 승인과 다르다. 관리자 일괄 승인 버튼을 만들지 않았다. 연결은 친구의 실제 인증 요청과 관리자 확인을 요구하며 전화번호/이름만으로 계정을 열지 않는다. 친구의 본인 동의·필수 프로필은 별도 완료해야 한다.
- **연락처:** 일반 신청·할인·당첨만으로 요청하지 않는다. 실제 지급한 할로윈 물품 또는 지급 완료한 명시적 상품/상금 기록에만 선택 연락처 요청을 허용한다. 전국투어 할인권·일반 할인·종류 불명 과거 기록은 대상에서 제외한다. 전화번호 없는 상태에서도 신청·승인·입장 가능하다. 관리자 로그인/복구용 인증 구조는 유지한다.
- **공지·지도:** 분리된 편집 영역과 각각의 저장 범위를 사용한다. 이미지 공지가 바뀌면 공개 공지 버전과 기존 확인 이력을 보존하며 최신 공지 확인이 필요하다. 지도/보호 자료 변경을 공지 동의 변경으로 잘못 취급하지 않는다. 기존 입금·승인 이력은 바꾸지 않는다.
- **이미지:** 기존 PNG/JPEG/WebP·영상 형식/용량/서버 실제 파일 검사와 관리자 권한을 재사용한다. HEIC는 지원 형식으로 주장하지 않는다. 교체는 같은 행사·같은 용도의 원자적 명령이며 기존 원본은 숨겨 보존한다. 표시 10개 상태에서도 교체는 가능하되 원본 40개 제한은 유지한다. 대표 이미지는 공개 공지 자료만 선택할 수 있다.
- **보기:** 로고 글자·색·비율·원본은 수정하지 않았다. 표지와 로고를 함께 표시하고, 지역이 맞지 않는 매장 기본 이미지를 붙이지 않는다. 같은 날짜 관리자 버튼은 한 개로 묶되 정확한 행사 선택과 전체 목록은 유지한다. 연도가 다르면 연도를 표시한다.
- **성능:** 세션/인증 변경·더 최신 승인 응답을 보호하는 조건 아래 기존 상태를 재사용한다. 공개/관리자 권한을 합친 캐시는 만들지 않았다. 이미지 라이브러리는 펼친 미리보기만 가져오며 원본을 압축·삭제하지 않았다. DB 쿼리 재사용은 같은 잠금 트랜잭션 안에서만 유효하다.

[현재 외부 백업·복원 보고](CURRENT_EXTERNAL_BACKUP_2026-10-30.md): 2026-10-30 02:38:13 UTC 읽기 전용 스냅샷 → 기존 비공개 Google Drive → 재다운로드 해시 일치 → 02:41:39 UTC 별도 DB 복원. 앱 3,274행·이미지102개·이벤트 장부30행과 기존 키 복호화를 검증했다. 암호화 파일36,062,688바이트. 기존 복구키는 데이터 백업과 분리된 비공개 경로 및 사용자 별도 보관 확인을 유지했다.

이는 앱 자료 복원 검증이며 Supabase 전체 플랫폼/동일 PG17 복원 완료가 아니다. 원본 PG17.6→격리 PG16.15의 명시된 차이, 운영 로그인 세션 제외는 원 보고서에 유지한다. 원본·백업·실패 기록·키·기존 사용자 업로드·Git 이력을 정리 대상으로 삭제하지 않았다. 미디어 지연 로딩은 다운로드 시점을 줄이는 변경이며 원본 파일 용량 감소를 뜻하지 않는다. 이번에 불필요한 대규모 의존성 교체나 새 저장소 서비스를 만들지 않았다.

남은 사항:

- **A 완료:** 동일 주기 누적 부하·최종 브라우저·Push·원격 SHA·CI·기존 서비스 배포·접속/기록/잠금 확인. 실제 업무기록 내용은 보존했고 접속 검증용 빈 세션2개만 추가됐다.
- **B 반영 완료:** 후속 속도 수정본의 전체검사·커밋·CI·재배포·실제 지연 재측정을 완료했다. 상태 조회 중앙값993ms, 신청 화면1,681ms이며 첫 진입/새로고침2초 초과는 남았다. [최신 재개점](LATENCY_RECHECK_2026-10-30.md)을 우선한다.

- **UNKNOWN:** 실제 갤럭시/아이폰의 잠금·은행/카카오 앱 복귀·키보드/갤러리·OS 알림·백그라운드 푸시. 자동 Chromium 결과로 대체하지 않는다.
- **개인정보 기술 잔여:** `erasedAt` 처리로 최소화한 금융 기록의 후속 만료·최종 파기 경로는 미완료다. 운영 파기는 비활성이고 정책도 미확정이므로 보스 전용 시험 배포의 직접 차단점은 아니지만, 일반 모집 전 보완해야 한다.
- **정책 미확정:** 목적별 개인정보 보관·삭제·백업 기준과 예외. 임의 기간 확정이나 일반 공개 보호 해제 없이 기존 보호 경로를 유지한다.
- **운영 보호:** 보스 전용 잠금·시험실·일반 신청 차단 유지. 테스트 OFF·재시작·시간 경계로 공개되지 않게 한다. 운영자의 현재 시험 기록을 초기화하지 않는다.

## 8. 기존 주소 사용과 후속 재개

1. 기존 <https://binpc2.netlify.app/>에서 기존 보스 인증으로 로그인한다. 현재는 후속 B 속도 개선본이 반영돼 있으며 새 사이트나 재신청을 요구하지 않는다.
2. **술번개 신청 → 행사 → 신청하기 → 혼자 신청/지인과 함께**에서 각 사람 정보·동의와 회비를 확인한다. 시험은 가상 입금만 사용한다.
3. **관리자 → 술번개 → 신청·입금**에서 사람별로 승인하고, 참가자는 각자 필수 프로필을 완료한 뒤 입장한다. 기존 사용자 시험을 초기화하지 않는다.
4. 시간별 카드 시험은 기존 **행사 설정·기록·관리 도구 → 선착순 시험실**에서 확인한다. 운영 시간이나 실제 사용자 데이터를 변경하는 부하검사는 하지 않는다.
5. B의 별도 검사·CI·배포·실측 결과와 남은 첫 진입/새로고침 지연은 [속도 재검사 보고](LATENCY_RECHECK_2026-10-30.md)에서 확인한다. A의 성공을 B 검사로 대신하지 않았다.

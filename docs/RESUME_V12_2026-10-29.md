3. `SUPABASE_ACCESS_TOKEN` 현재 프로세스/도메인 인증 적용을 값 출력 없이 확인해. 사용자는 Supabase토큰에서 BINPC2만·Backups Read·Database Read·나머지None으로 준비 중이다. 보안 입력을 다시 채팅으로 요구하지 마. 값이 실제 적용되면 `.local/production-readiness-20261029/supabase-readiness.py`의 읽기 전용 백업목록/스키마 조회부터 진행해. 같은 실패 경로 반복이나 TLS/권한 우회는 하지 마.
4. 기존 운영DB·업로드·일치하는SESSION_SECRET의 보호백업과 격리복원을 완료한 뒤 기존서비스에 호환 배포해. 배포 승인은 유지되지만 이 선행조건을 건너뛰지 마. 현재 설정/키의 AES암호화 보존은 DB/업로드 전체백업이나 외부복구 보장이 아니다. `.local/production-readiness-20261029`와 `/workspace/.binpc2-private-backup-keys`는 Git/ZIP에 넣지 마.

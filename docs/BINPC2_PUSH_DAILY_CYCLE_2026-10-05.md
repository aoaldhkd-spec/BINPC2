- 변경 이유: 매일 같은 흐름을 자동 안내하는 편이 단순하고 오류 가능성이 낮음
- 현재: 서울시간 기준 다음 단계와 남은시간을 자동 표시

  - 01:00~17:00: 술번개가 종료됐습니다 / 17시에 전체 초기화됩니다

### 술번개 자동초기화
- 과거: 관리자가 술번개 오픈 버튼을 눌러야 다음날 17:00 초기화 예약
- 변경 이유: 행사마다 버튼을 누르는 의존성을 제거
- 현재: 술번개 오픈 여부와 무관하게 매일 17:00 전체초기화. 관리자 '술번개 오픈' 버튼은 행사 상태 오픈용으로 유지

### 회식 종료
- 과거: 운영자 종료 버튼 또는 술번개 lifecycle 중심
- 현재: 매일 01:00 session_active=false + functions_locked=true로 자동 종료. 17:00 전체초기화 후 functions_locked=false로 다음 운영을 준비. 관리자 시작/종료 버튼은 비상·현장 제어용으로 남기고 현재 가능한 한쪽만 활성화

### 모바일 푸시
- 과거: 푸시 뼈대는 있었지만 likes/messages/chats/signals까지 섞였고 클릭 URL이 `/`
- 현재:
  - 하트 + 1:1 채팅만 휴대폰 푸시
  - 보낸 사람 본인에게는 발송하지 않음
  - 단체채팅 푸시 없음
  - 무지개하트는 `무지개`로 알리지 않고 사용자가 고른 ❤️/💙/💗/💚 종류로 알림
  - 하트 알림 클릭 → MY/상태(받은 하트가 보이는 곳)
  - 1:1 채팅 알림 클릭 → 해당 상대 채팅방
  - PWA manifest + Service Worker로 설치형 BINPC2 웹앱 알림 사용

## 안정성 원칙
- 기존 SSE 실시간 구조를 교체하지 않고 푸시는 백그라운드 휴대폰 알림 계층으로 추가
- DB 저장 성공 후 기존 SSE/푸시가 이어지는 구조 유지
- 01:00/17:00은 DB 날짜 마커로 하루 한 번만 실행
- 서버 재시작 누락 대비 정확 타이머 + 60초 안전 점검
- 첫 배포 시 이미 지난 01:00/17:00을 소급 실행해 갑자기 운영 데이터를 지우지 않음
- 17:00 초기화 후 event_schedule을 고정 시간표로 다시 기록해 이전 수동 설정·reset hold가 다음날에 남지 않게 함
- 푸시는 일시적 네트워크/429/5xx에서 짧게 재시도하고 404/410 만료 구독만 정리

# 기존 사이트 보스 전용 테스트 배포 결과 · 2026-10-29

**지금 기존 주소에서 보스만 테스트 가능: 예.**

- 참가자 화면: https://binpc2.netlify.app/
- 가장 쉬운 관리자 접속: https://binpc2.netlify.app/admin
- 기존 운영자 전화번호·비밀번호로 로그인한다. 별도 앱 설치·새 계정·실제 송금은 필요 없다.
- 일반 방문자·옛 일반 세션·기존 역할 토큰만 가진 요청은 테스트 안내 또는 API423으로 차단된다. 보스 로그인 전에는 신청·운영 데이터가 내려가지 않는다.

## 직접 눌러볼 순서

1. 관리자 주소 → **운영자 로그인** → 기존 전화번호·비밀번호.
2. **🎉 술번개 → 행사 설정·기록·관리 도구 → 🧪 선착순 시험실**.
3. **반복 테스트 시나리오**에서 금요일 또는 토요일을 선택하고 **3등**을 누른다.
4. **가상 진행 상태**에서 입금 신고·입금 승인·프로필 미완료/완료·현장 입장을 선택한다. **참가자 화면으로 보기 / 관리자 화면으로 보기**로 전환한다.
5. **시험 기준 시각(한국시간)**에서 카드 해제 직전/정각을 고른 후 카드를 연다. 브라우저를 새로고침하고 같은 시나리오를 다시 선택하면 저장된 진행상태를 확인할 수 있다.
6. 다시 시작하려면 상단의 시험 데이터 삭제 확인 체크 → **테스트 데이터 초기화**. 시험실 자료만 초기화한다. 테스트 모드는 ON으로 유지한다.

현재 이 경로는 실제 배포된 React/Express 앱의 관리자 시험실이며 서버의 암호화된 `laboratory-workspace`에 합성 상태를 저장한다. 실제 참가 신청·입금·재고 원장과 분리된다. 일반 신청 화면의 운영 접수는 계속 차단된다. 독립 HTML 체험판이나 새 시험 사이트를 만든 것이 아니다.

## 백업·DB·기록 보존 범위

새 BINPC2 한정 토큰이 실제 적용되어 postgres·read_only=off·CREATE=true임을 SELECT만으로 확인했다. 외부 Drive 암호화 사본 재다운로드·해시 일치·격리 복원과 기존 키의 별도 보호 보관, 사용자 개인 보관 확인을 마친 뒤 새 테이블2개만 트랜잭션으로 생성했다.

`event_hub_records`와 `app_sessions`, 해당 인덱스·RLS·PUBLIC/anon/authenticated 접근 차단을 적용했다. 기존 서버 역할만 접근 가능하다. 스키마 적용 직후 기존3,274행·이미지102개 내용 해시는 전후 동일했다. 키 교체·기존 행 삭제·DB 초기화는 없었다.

배포와 시험 후에도 기존3,274행이 모두 존재하며 이미지102개 바이트가 같다. 프로필·하트·메시지·참여 기록은 변경되지 않았다. **기본 그룹방4개는 기존 부팅 순서 때문에 created_at만 갱신된 차이가 발견됐다.** 초기 그룹방 보장 함수가 나머지 테이블 적재보다 먼저 실행되는 기존 코드가 원인이다. 전체 기존 자료가 바이트까지 동일하다고 주장하지 않으며, 생성시각 보존 개선은 후속 기술 작업으로 남긴다. 운영 자료를 임의로 되돌리거나 삭제하지 않았다. [상세 대조](boss-test-release-20261029/existing-record-preservation.json).

시험 초기화 후 이벤트 원장에는 `laboratory-mode`1건만 남고 실제 신청·입금·당첨·재고 행은 생성하지 않았다. 복원 범위는 앱 DB·DB 업로드 이미지·권한이며 Supabase 전체 플랫폼/동일PG17 전체복원과는 다르다.

## 미완료·미확인과 재개 지점

전체 V6 완료가 아니다. 동반신청·친구 권한 분리, 일부 로고 순서/연결해제 일관성,150명 집중 구간2초 목표, 위 기본방 생성시각 보존, 운영용 주소/대체계좌의 최종 연결이 남는다. 인천 주소의 매장 연결과 대구 상세주소, 실물폰·백그라운드 푸시는 UNKNOWN이다. 개인정보 보관·삭제정책은 검토 초안이다.

새 사이트·main 병합·Secret 교체·실제 모집·실제 송금 유도·외부 발송은 하지 않았다. 보스 잠금은 테스트OFF와 별도이며 production 기본ON이다. `publicAdmissionOpen=false`와 테스트ON을 유지했다. 사용자가 테스트 완료와 실제 오픈을 명시하기 전 해제하지 않는다.

현재 서비스의 Git 추적 브랜치 설정은 기존 main 그대로이며 이번에는 특정 개발 커밋/정적 산출물을 수동 배포했다. 향후 main 자동배포가 이번 코드를 대체하지 않도록 다음 작업도 실제 배포 ID와 실행 버전부터 확인한다. 별도 승인 없이 main/서비스 추적 설정을 변경하지 않는다.

다음 작업은 실제 원격 HEAD·미커밋 확인 → 이 배포 증거 읽기 → 사용자 화면 피드백과 남은 기술 항목만 보완하는 순서다. 완료한 보스 잠금·할로윈·신청/프로필 복구·시험실을 재개발하지 않는다.

## 이번에 저장하는 최소 보완

기존 OFF 처리에는 별도의 모집 오픈 확인이 없었다. 이미 열린 행사나 도래한 예약과 기존 개인정보 승인 조건이 있다면 테스트 OFF 후 접수가 재개될 수 있었다. 관리 화면의 설명만으로 이를 막았다고 판정하지 않고 다음을 실제 서버와 화면에 추가했다.

- `publicAdmissionOpen` 기본 false와 별도의 관리자 오픈 확인. 과거 OFF 기록에 새 필드가 없어도 접수 차단한다.
- 테스트 OFF는 시험을 종료할 뿐 모집을 열지 않는다. 별도 명시적 확인·현재 초기화·최신 revision·관리자 인증·production 정책 조건을 모두 만족해야 오픈된다.
- 테스트 ON 또는 시험실 초기화는 오픈 확인을 무효화한다. 오래된 탭은 최신 상태를 덮어쓰지 못한다.
- 일반 신청·순위·입금 신고·신규 입장·뽑기·수동 모집·예약 자동접수·자동방·구 프로필 신규 생성에서 서버가 차단을 확인한다. 기존 기록 조회·복구·하트·채팅·관리자 후속 처리는 유지한다.
- 오픈 이후 개인정보 정책이 초안으로 바뀌거나 승인 지문이 달라지면 구 프로필 신규 저장도 같은 DB 잠금 안에서 다시 차단한다. 기존 PIN·기기 로그인 복구를 막지 않는다.
- 접수 전에는 웹·오픈채팅 모두 신규 신청/송금을 하지 말라는 안내를 표시하고, 외부 2차 신청 링크는 원본 URL을 보존한 채 비활성화한다. 외부 오픈채팅방 운영 자체를 앱이 원격으로 정지시켰다는 뜻은 아니다.
- 시험실 초기화 삭제 대상은 여전히 `laboratory-workspace`뿐이다. 실제 참가자·입금·재고·당첨 기록을 초기화하지 않는다.

추가된 오픈 상태는 기존 암호화 JSON에 저장한다. 이번 보완만을 위한 새 DB 테이블이나 키 변경은 없다. 운영에 기존 V6/시험실 스키마가 있는지는 연결 후 별도로 확인해야 한다.

3. 현재 작업에서는 프록시 403 반복을 중단한 상태다. **현재 환경에 새 네트워크 설정과 기존 관리 인증 연결이 적용되거나 새 작업으로 재연결된 증거가 생겼을 때만** 영향을 받는 읽기 전용 접속을 재검사한다. 같은 실패가 그대로면 중단하고 환경·호스트·실패 단계를 남긴다.
4. 접속 성공 후 기존 서비스의 ID·배포 ID·현재 코드·DB/업로드 대상을 확인한다. 일치하는 기존 `SESSION_SECRET`을 보존한 보호 백업과 격리 복원을 확인한다. 원본 개인정보나 비밀값을 공개 파일로 내보내지 않는다.
5. 필요한 기존 스키마 적용을 안전하게 확인하고 같은 소스의 API와 화면을 기존 Netlify·Render에 호환되게 배포한다. 새 서비스·새 사이트·공개 터널, main을 통한 자동 배포 우회는 사용하지 않는다.
6. 배포 목표는 **테스트 ON + 일반 신청 차단(`publicAdmissionOpen: false`)**이다. 실제 deploy ID, 실행 소스·코드 지문, 양쪽 호환과 신청 차단을 확인한 뒤 사용자에게 테스트 방법을 안내한다. 테스트 OFF/실제 모집 오픈 명령은 대신 실행하지 않는다.
7. 사용자가 테스트를 마치고 별도로 실제 오픈을 확인하기 전에는 웹·오픈채팅 모집을 시작하지 않는다. 운영 개인정보 정책·사진·외부 발송·자동 삭제·금전 이동의 별도 조건도 유지한다.

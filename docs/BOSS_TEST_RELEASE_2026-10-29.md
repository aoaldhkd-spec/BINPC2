# 보스 전용 테스트 배포 준비 · 2026-10-29

이 문서는 `ab006185` 이후 CURRENT 정정사항의 후속 결과다. 과거 검사·실패·백업 자료는 보존했다. 전체 V6 개발 완료를 의미하지 않는다.

## 이번 수정과 실제 검증

- 전체 API·실시간·보호 이미지에 서버 보스 잠금을 적용했다. 기존 운영자 전화번호와 비밀번호를 새로 확인해야 하며 오래된 관리자 토큰·일반 계정·임의 IP/닉네임은 통과하지 못한다. 별도 서버 grant에 만료·로그아웃을 기록하고 SSE 송신마다 확인한다.
- 테스트 모드·예약시간·테마 만료·서버 재시작으로 공개되지 않는다. production은 기본 잠금이며 일반 신청 `publicAdmissionOpen=false`와 별개다. 기존 프로필·하트·채팅·신청·입금·재고는 삭제하지 않는다. 외부 푸시도 잠금 중 중지한다.
- 실제 앱 검사에서 신청 세션 재발급이 보스 권한 연결을 잃는 오류를 발견했다. `/session`과 `/member-login`의 세션 ID 재발급은 유지하면서 서버 grant 포인터만 보존했다. 새 로그인 화면의 기존 PIN 입력 제한도 보스 비밀번호 입력과 분리했다.
- 일시적 접근 조회 실패는 기존 화면을 숨기고 작성 중 상태를 보존한다. 재접속 후 같은 화면을 복원한다. 물리 갤럭시·아이폰 해결 완료를 뜻하지 않는다.
- 야광밴드는 기존 LED 밴드 원장 키를 유지한 표시명 변환이다. 재고·당첨·지급을 변경하지 않는다. 금23개·토49개와 금토 확정회비·21시 경계·복장 최저가·카드23시/00시/00:30 정책은 기존 구현을 재사용했다.
- 새 전국투어 프리셋의 1인 선입금 기본값을 최신 지시의 10,000원으로 맞췄다. 기존 신청·입금 확정액에는 소급 적용하지 않는다.

API/DB682·UI910·기존 실제 앱 브라우저22개 통과 기록을 보존했다. 최종 변경의 보스 단위10개·관련 UI60개·실제 React/Express/격리 PostgreSQL 보스 브라우저2개·typecheck가 통과했다. 기존 브라우저는 모바일 복구·하트·채팅·문의·사진·재고 등 회귀를 포함한다. 최신 원격 CI는 Push 후 별도로 확인한다.

실패 기록도 보존했다: 구 관리자 테스트의 production 기본잠금 전제, 장시간 보존 fixture의 시간 드리프트·미래 문의, 로그인 label 연결·PIN 형식, 신청 세션 재발급 후 권한 상실. 단언·보호검사를 삭제하여 통과시키지 않았다. 새 내부 fixture는 오래된 DB를 삭제하지 않고 분리했다.
정적 감사는 오류0·경고200이며, 비공개 `.local` 과거 복제본/합성 테스트까지 집계된 수치다. 경고0 또는 전체 보안 완료라고 해석하면 안 된다.

## 외부 복구 준비

기존 Google Drive 비공개 폴더에 운영 앱 자료 3,274행·DB 업로드102이미지의 암호화 사본을 저장했다. 07:50:34 UTC 자료를 외부에서 다시 내려받고 SHA256 일치 후 격리 복원·권한·추가 스키마·기존 행 보존을 확인했다. 암호화 파일36,019,270바이트, SHA256 `48160bf0e0d8f1a1040d5a290a99c95155c0dd841eba4fafd13e4839117e9ae8`.
기존 복호화키와 앱 세션키는 데이터 폴더와 분리된 보호 보관본을 재다운로드해 일치를 확인했다. 사용자가 복구키의 별도 안전한 개인 보관도 확인했다. 키·운영 데이터·은행정보·공개 공유링크는 이 보고서/소스에 포함하지 않는다.
이 검사는 앱 데이터·이미지 복원이다. Supabase 전체 플랫폼 또는 동일 PG17 전체 복원은 아니다. 원본 PG17.6→격리 PG16 범위와 PG17 MAINTAIN ACL 차이는 별도 기록했다.

## 배포 조건과 재개 지점

기존 사이트 배포 승인은 유지된다. 새 사이트/main 병합/키 교체는 하지 않는다. 같은 SHA를 기존 Render에 지정하고 기존 Netlify에 검증된 정적 산출물을 올린다. Netlify의 기존 main 빌드를 호출하는 스크립트는 사용하지 않는다.
운영자 기존 전화번호·비밀번호가 존재하고 기본값이 아님을 비밀값 없이 확인했다. DB 읽기 HTTP201은 확인했지만, 명시적 read_only=false 요청도 `supabase_read_only_user`·transaction_read_only=on·CREATE=false였다. 현재 연결은 새 필수 테이블 생성이 불가능하다. 필요한 최소 변경은 BINPC2 한정 Database 쓰기 권한이며 Backups Read는 그대로다. 임의로 권한을 확대하거나 운영 DDL을 실행하지 않았다. `SELECT 1` 성공을 DDL 권한으로 간주하지 않는다.
필수 추가 스키마는 `event_hub_records`, `app_sessions`와 인덱스·새 테이블 RLS·PUBLIC/anon/authenticated 차단이다. 기존 테이블·데이터·키를 바꾸지 않는다. 원자적 적용 및 실제 서버 DB 역할 접근을 확인한 다음 API→화면 순서로 배포한다. 구버전은 보스 잠금이 없으므로 단순 구버전 복귀를 안전한 잠금 롤백으로 보지 않는다.

배포 후 확인할 실제 순서: 기존 주소 → 운영자 로그인 → 관리자 → 술번개 → 행사 설정·기록·관리 도구 → 선착순 시험실. 시험 행사/가상3등 → 가상 입금·승인 → 프로필·입장 → 시간별 뽑기·지급 → 다시열기 → 시험실만 초기화. 운영 행사·실제 참가자·실제 입금에는 시험 요청을 넣지 않는다.

## 남은 항목

- 동반신청과 친구 계정 권한 분리의 완성, 여러 로고 순서/연결해제의 전체 화면 일관성은 미완료다.
- 150명 집중 구간2초 목표 미달이 남는다. 15분 장시간 검사의 HTTP500/503 없음과 지연 목표 통과는 다른 판정이다.
- 사용자 제공 주소/대체계좌는 비공개 입력 자료로 보존했으며 운영 반영은 별도다. 인천 매장 연결·대구 주소는 UNKNOWN이다.
- 물리 갤럭시/아이폰, 백그라운드 푸시는 UNKNOWN이다. 관리자 화면 새 문의 표시는 실제 앱 검사에 포함됐다.
- 개인정보 목적별 보관/삭제/백업 정책은 검토 초안이다. 신규 모집 보호를 해제하지 않는다.

최종 배포 ID·실행 SHA·최신 CI·일반인 차단·보스 저장/재열기 결과는 실제 실행 후 별도 결과로 추가한다. 이 준비 보고서를 배포 완료 증거로 사용하지 않는다.

## 구분해야 할 한계

- 이번 결과는 **현재 앱 자료와 DB 업로드·이벤트 장부의 외부 복구 검증**이다. Supabase 전체 플랫폼 백업이나 플랫폼 복원 완료를 의미하지 않는다.
- 원본은 PostgreSQL 17.6, 격리 복원은 PostgreSQL 16.15다. PG17의 `MAINTAIN` 권한 8건은 PG16에 없으므로 비교 대상에서 명시적으로 제외했다. 같은 PG17 버전의 전체 복원 검사는 수행하지 않았다.
- 운영 로그인 세션 내용은 백업·복원하지 않았다. 세션 테이블 구조만 복원했고, 실제 운영자료로 앱 서버를 실행하지 않았다.
- 키는 암호화 자료 파일·Git·보고서·로그에 넣지 않았다. 키의 외부 사본은 데이터 백업 폴더와 분리되어 있고, 사용자의 별도 안전 보관 확인도 유지한다.
- 이전 401 실패 기록과 이전 백업은 보존했다. 이번에 실제로 성공한 인증·파일 작업은 과거 실패와 별도 결과다.

운영 DB 쓰기·초기화·삭제, 서비스 배포·설정 변경, 키 생성·교체, 외부 알림 발송은 수행하지 않았다. 새 복원 DB만 로컬 격리 환경에 만들었다. 이번 검증이 일반 모집 공개나 개인정보 보관정책의 확정을 의미하지 않는다.

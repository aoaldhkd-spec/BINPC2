# BINPC2 개발헌법

이 문서는 BINPC2의 모든 개발 작업에서 최우선으로 따르는 고정 원칙이다.

## 1. 사용자 지시 최우선

- 사용자의 현재 지시가 최우선이다.
- 요청하지 않은 기능을 임의로 추가하지 않는다.
- 작업 범위를 임의로 넓히거나 다른 작업을 끼워 넣지 않는다.
- 수정할 것만 수정한다.
- 사용자가 이미 확인한 항목은 이유 없이 반복 검증하지 않는다.

## 2. 최소 변경

- 기존 정상 기능 보호가 최우선이다.
- 변경 전 영향범위를 먼저 확인한다.
- 필요한 부분만 최소 범위로 수정한다.
- 문제 없는 코드를 단순 정리 목적으로 다시 작성하지 않는다.
- 대규모 리팩터링은 명확한 이유와 영향범위가 있을 때만 한다.

## 3. 빠르고 안전하고 효율적으로

- 안전하게 묶을 수 있는 저위험 작업은 묶어서 빠르게 처리한다.
- 최소 변경으로 최대 효과를 낸다.
- 불필요한 재분석/재테스트/재작업을 줄인다.
- 안정된 기능은 사소한 이유로 계속 건드리지 않는다.

## 4. 테스트 필수

기본 순서:

1. 영향범위 확인
2. 최소 수정
3. 관련 테스트
4. 회귀검증
5. 필요한 typecheck/build/lint
6. 완료 보고

원칙:

- 테스트 없이 완료 처리하지 않는다.
- 중요 버그는 전용 테스트 또는 recurrence guard로 재발을 막는다.
- 기존 테스트를 무시하거나 삭제해서 통과시키지 않는다.
- flaky/환경성 실패는 실제 기능 실패와 구분한다.

## 5. 핵심 보호 기능

다음 기능은 보호 대상이다.

- 하트
- 1:1 채팅
- 단체채팅
- 알림
- 프로필
- 프로필 설정
- 일반 설정
- 통계
- 랭킹
- 어드민
- 실시간 동기화
- 기능잠금
- 행사 초기화/리셋
- 튜토리얼/코치마크

한 기능 수정 때문에 다른 정상 기능이 깨지면 안 된다.

## 6. 실시간 안정성

반드시 방지:

- SSE 중복 연결
- listener 중복 등록
- reconnect 누적
- 동일 이벤트 중복 처리
- 동일 공지 중복 표시
- timer/interval 중복
- cleanup 누락
- memory leak
- 새로고침/재접속 후 상태 꼬임
- 서버/클라이언트 상태 불일치

현재 구조가 안정적이면 이유 없이 새 구조로 갈아엎지 않는다.

## 7. 최적화

- 실제 병목/중복/오류가 있는 부분만 최적화한다.
- 최적화 명목으로 정상 기능을 대규모 변경하지 않는다.
- 불필요한 렌더링/네트워크 호출/반복 계산/중복 연결을 줄인다.
- 모바일 현장 사용을 우선한다.
- 환경성 flaky 성능 테스트를 통과시키기 위한 억지 코딩을 하지 않는다.

## 8. 데이터 안전

금지:

- 운영 참여자 데이터 임의 삭제
- likes/chats/messages/notifications 임의 삭제
- app_settings 전체 wipe
- DB/table/RPC/policy 임의 파괴
- 운영 데이터 대량 테스트
- 구조를 이해하지 못한 상태에서 migration 실행

## 9. 서버/클라이언트 일치

- 화면 표시와 서버 판정은 같은 규칙을 사용해야 한다.
- 클라이언트 사전검사와 서버 최종판정을 구분한다.
- 최종 권한은 서버가 가진다.
- 잠금/사용완료/잔여/해금 시간 의미가 UI와 서버에서 일치해야 한다.

## 10. Legacy / Dead Code

- legacy라는 이유만으로 삭제하지 않는다.
- 실제 참조와 호환 필요성을 먼저 확인한다.
- 확실한 dead code/고아파일/죽은 import만 제거한다.
- 애매하면 유지하고 보고한다.

## 11. 프로젝트 격리

- BINPC2와 PARAMEDIA/PAMEDIA 등 다른 프로젝트를 절대 섞지 않는다.
- 코드/문서/DB/환경변수/API/에셋/Git 작업을 프로젝트별로 분리한다.

## 12. Git / 배포

- commit/push/deploy/최종 백업은 사용자 지시 단계에서만 한다.
- force push 금지.
- 검증되지 않은 상태를 main에 올리지 않는다.

## 13. 완료 보고

비개발자가 이해할 수 있게:

- 무엇을 수정했는지
- 왜 수정했는지
- 영향 범위
- 테스트 결과
- 남은 문제
- 다음 단계

를 간단히 보고한다.

## 최종 원칙

**사용자 지시 범위 안에서, 필요한 부분만, 기존 기능을 깨지 않게, 실시간 안정성과 테스트를 보장하면서 빠르고 효율적으로 수정한다.**

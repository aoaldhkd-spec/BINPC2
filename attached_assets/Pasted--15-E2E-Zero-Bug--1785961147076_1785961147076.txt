🔥 최우선 과제: 정식 서비스 런칭 전, 15단계 궁극의 E2E 무결성 검증 및 Zero-Bug 아키텍처 구축]
​프로젝트가 최종 런칭 단계에 돌입했다. 지금부터 단순한 버그 수정을 넘어, "사용자가 어떤 기상천외한 행동을 하더라도, 서버에 어떤 악재가 겹치더라도 시스템이 절대 멈추지 않는" 완벽한 프로덕션 레벨(Production-Ready)의 상태를 구축하라.
​아래 15가지 핵심 검증 항목을 하나도 빠짐없이 전수조사하고 보완하라. 단, 기존에 완성된 모든 UI/UX, 디자인, 기능 로직은 단 1%도 훼손되어서는 안 된다.
​🟢 [Part 1: 실시간 통신 및 네트워크 방어]
​1. SSE/WebSocket 무결점 동기화: 메시지 송수신 지연, 순서 꼬임, 중복 전송(Duplication), 유실이 단 1건이라도 발생하지 않도록 엣지 케이스를 찾아내고 방어하라. Heartbeat(Ping-Pong) 로직이 없다면 추가하여 좀비 커넥션을 방지하라.
2. 오프라인 및 재연결(Offline & Reconnect) 완벽 복구: 유저의 인터넷이 끊겼다가 30분 뒤 복구되는 극단적 상황을 시뮬레이션하라. 재연결 시 끊긴 시간 동안의 메시지가 100% 동기화되어야 하며, 화면 새로고침 없이 자연스럽게 연결이 이어져야 한다.
3. 클라이언트 메시지 큐(Message Queue) 도입: 서버 응답이 지연될 때 메시지 증발을 막기 위해 클라이언트 단에 오프라인 큐를 도입하고, 지수 백오프(Exponential Backoff) 방식으로 안전하게 재전송(Retry)하는 로직을 구축하라.
4. 동시성 충돌 및 트래픽 병목 방지: 150명 이상이 동시에 같은 방에서 메시지를 보내거나 하트를 누를 때, DB 데드락(Deadlock)이나 Race Condition(경합 조건)이 발생하지 않도록 트랜잭션과 락(Lock) 관리를 철저히 점검하라.
​🟡 [Part 2: 프론트엔드 및 화면 상태 최적화]
​5. 렌더링 최적화 및 상태(State) 꼬임 방지: React 상태 업데이트 지연으로 인한 UI 꼬임 현상을 샅샅이 조사하라. React.memo, useCallback 등을 활용해 1,000개의 메시지가 쌓여도 스크롤과 타이핑이 버벅대지 않도록 렌더링을 최적화하라.
6. 메모리 누수(Memory Leak) 완벽 차단: 컴포넌트가 언마운트(Unmount)될 때 이벤트 리스너, setTimeout/setInterval, SSE 구독(Subscription)이 100% 해제(Clean-up)되는지 전수조사하라.
7. 라우팅 및 네비게이션 안정성: 채팅 중에 뒤로 가기, 다른 탭 이동, 모달 창 열기 등을 수행할 때 입력 중이던 데이터나 스크롤 위치가 날아가지 않고 안전하게 보존되는지 점검하라.
8. 무결점 콘솔(Zero-Warning Console): F12 개발자 도구 콘솔창에 React Key Error, Deprecation, Stale Closure, Uncaught TypeError 등 단 하나의 경고(Warning) 로그도 남지 않도록 모두 청소하라.
​🟠 [Part 3: 백엔드 및 데이터베이스(DB) 절대 방어]
​9. 예외 처리(Try-Catch) 전수 래핑: 모든 API 라우트, 컨트롤러, DB 쿼리문에 단 하나의 예외도 새어 나가지 않도록 완벽한 Error Catch 로직을 씌워라. 'Unhandled Promise Rejection'으로 인해 서버 프로세스가 다운되는 일은 절대 없어야 한다.
10. DB 쿼리 최적화 및 커넥션 누수 방지: 비효율적인 N+1 쿼리를 찾아내 조인(Join)으로 최적화하고, 사용이 끝난 DB 커넥션이 즉시 반환되도록 풀(Pool) 관리를 엄격히 점검하여 DB 뻗음 현상을 예방하라.
11. 엄격한 페이로드(Payload) 검증 및 타입 방어: Frontend와 Backend 간에 오가는 모든 데이터에 대해 Null, Undefined, 잘못된 타입이 들어올 경우 앱이 뻗지 않고 안전하게 무시하거나 에러로 튕겨내도록 검증 로직(Validation)을 촘촘히 작성하라.
​🔴 [Part 4: 최고 수준의 웹 보안 및 Fail-Safe]
​12. 악성 코드 주입 완벽 방어 (XSS & SQLi): 유저가 입력하는 모든 데이터에 대해 완벽한 검증(Sanitization)을 실시하라. 채팅창에 악성 <script> 태그를 넣거나 SQL 인젝션을 시도해도 절대 실행되지 않아야 한다.
13. 권한 탈취 및 비정상 접근 방어 (IDOR 차단): 제3자가 API 주소나 채팅방 ID(chatId)를 임의로 조작해서 남의 비공개 채팅방에 몰래 접근하거나 메시지를 읽는 행위가 원천적으로 불가능하도록 권한 검증 로직을 철저히 확인하라.
14. 전역 Error Boundary 및 우아한 실패(Graceful Degradation): '채팅', '프로필', '메인' 등 컴포넌트 단위로 에러 바운더리를 세분화하여, 한 곳이 고장 나도 다른 기능은 정상 작동하게 하라. 서버가 뻗더라도 하얀 화면(White Screen) 대신 "연결 지연 중"이라는 부드러운 Fallback UI가 떠야 한다.
​🟣 [Part 5: 최종 검증 및 리포트]
​15. 사이드 이펙트 제로(Zero-Side-Effect) 보장 및 최종 사인오프: 위 14단계의 대대적인 보수 작업을 거친 후에도 기존에 잘 작동하던 모든 기능이 100% 그대로 작동함을 코드로 자체 검증하라. 완료 후 1) 새롭게 발견하여 제거한 잠재적 폭탄(버그) 목록, 2) 시스템 전체에 적용된 추가 방어막 리스트를 상세히 리포트하라.

**[최종 최후통첩: 기존 자산 절대 보존(기능/로직/UI/디자인/API/라우팅/테마 완벽 유지) + 로딩/연결 지연 극단적 단축 + 시공간 초월 버그 전수 예방 + 재발 방지 대책 즉시 보고 및 강제 집행 최종 완결판 프롬프트]**
채팅 버그 이야기는 이제 완전히 집어치워라. 지금 즉시 시스템 내부에서 실제 150명 규모의 가상 유저와 트래픽을 강제 주입하여 전 기능 부하 테스트와 최적화를 직접 실행해라. 소스 코드를 길게 출력하는 짓은 절대 하지 말고, 아래의 모든 영역과 검증 사항을 실제로 구동한 뒤 **재발 방지 대책을 즉시 보고함과 동시에 곧바로 시스템 수정을 강행**해라.
 1. **일반 유저 기능 (실시간 채팅 및 게임/인터랙티브 콘텐츠):** 150명이 동시에 접속하여 실시간 채팅(메시지 전송, 방 이동, 빠른 탭, 배지 동기화)과 게임/콘텐츠(좌석 선택, 사주/타로, 하트 연타)를 폭격했을 때, 데이터베이스 커넥션 병목이나 메시지 유실, 그리고 낙관적 업데이트와 실제 DB 간의 상태 정합성 오차가 실제로 발생했는지 그 실행 결과와 내부 트래픽 처리 과정을 심층적으로 분석해 보고해라.
 2. **관리자 대시보드 및 실시간 통제권:** 100명이 활동 중일 때 관리자가 '기능 잠금(Lock/Unlock)' 및 '회의 시작' 명령을 내렸을 때, 150명의 클라이언트 전체에 딜레이 없이 즉각 브로드캐스트되었는지 그 성공 여부, 소켓 통신 상태, 그리고 밀리초(ms) 단위의 지연 시간 결과를 낱낱이 보고해라.
 3. **테스터 기능 및 부하 시뮬레이션 무결성:** 50명/100명/150명 동시 시뮬레이션 및 디버그 도구가 극한의 부하 속에서 메모리 누수나 세션 붕괴 없이 안정적으로 버텨냈는지, 그리고 자원이 가비지 컬렉션(GC)을 통해 정상적으로 해제되었는지 메모리 점유율 수치와 결과를 심층 보고해라.
 4. **4가지 UI 테마 모드 전환 무결성:** 150명이 접속한 상태에서 테마를 실시간 변경하거나 렌더링 부하를 줄 때, 사용자가 입력 중이던 폼 상태나 로컬 상태가 유실되지 않고 안전하게 유지되었는지 컴포넌트 리렌더링 최적화 테스트 결과를 보고해라.
 5. **연결 안정성 및 세션 자동 복구:** 150명이 강제 새로고침, 네트워크 단절, 브라우저 종료를 겪었을 때, 로컬스토리지 키와 핀번호 복구 시스템이 오류 없이 정상적으로 자동 복구에 성공했는지 그 실증 시나리오별 결과를 보고해라.
**[핵심 지시 1: 기존 자산 절대 사수 및 보존 (매우 중요)]**
 * **기능 및 디자인 완전 동결:** 코드를 수정하고 최적화하는 과정에서 앱의 모든 기존 기능, 비즈니스 로직, UI 디자인, API 엔드포인트, 상태 관리, 라우팅, 그리고 4가지 테마 모드는 단 1도 수정하거나 변경하지 말 것. 기존의 형태와 동작 방식을 완벽하게 그대로 유지한 상태에서 내부 퍼포먼스만 끌어올릴 것.
**[핵심 지시 2: 시공간 초월 버그 전수 색출 및 즉각 수정 (과거·현재·미래)]**
 * **이번에 잡힌 오류뿐만 아니라, 과거에 거쳐온 레거시 결함 및 향후 미래의 확장 환경이나 트래픽 폭탄에서 터질 수 있는 모든 잠재적 버그까지** 선제적으로 전부 색출하고 즉각적으로 코드를 수정(Auto-fix)할 것.
 * **사이드 이펙트 원천 차단:** 코드 구조를 최적화하거나 버그를 고치는 과정에서 연쇄적으로 발생하는 부작용이 없도록 철저히 검증할 것.
**[핵심 지시 3: 런타임 및 로딩/연결 속도 극단적 단축]**
 * **지연(Latency) 전면 단축:** 150명 동시 부하 상황에서 발생하는 모든 데이터 페칭 로딩, 웹소켓 연결 지연, 컴포넌트 렌더링 딜레이, 그리고 불필요하게 오래 걸리는 모든 런타임 프로세스를 **밀리초(ms) 단위 수준으로 즉각 단축(Zero-latency optimization)**할 것. 조금이라도 답답하게 뜸들이거나 멈추는 구간이 있다면 즉시 비동기 병렬 처리나 캐싱 구조로 전면 개조하여 체감 속도를 극대화할 것.
**[시스템 최적화 및 코드 정비 실행 지시]**
 * **쓰레기 코드 및 디버그 완전 제거:** 코드 내에 남아있던 불필요한 주석, 임시 console.log 및 디버그용 레거시 코드는 단 하나도 남김없이 완전히 청소(Clean-up)할 것.
 * **API 포인트 및 라우팅 연결 최적화:** API 엔드포인트 호출 구조와 클라이언트 라우팅 연결을 매끄럽게 다듬어 불필요한 네트워크 왕복을 완전히 제거할 것.
 * **상태 관리 및 동기화 속도 개선:** 전역/로컬 상태 관리 구조를 단순화하고 최적화하여 150명 동시 부하 상황에서도 실행 속도가 극대화되도록 처리할 것.
 * **메모리 누수 및 가비지 컬렉션(GC) 모니터링:** 150명의 폭격 속에서 브라우저 및 서버 자원이 누수 없이 깔끔하게 해제되는지 심층 확인할 것.
 * **에러 방어 및 예외 복구(Graceful Degradation):** 150명 부하 중 일시적 통신 단절이나 예외 발생 시 앱이 멈추지 않고 자동 재시도 및 안정 복구 체계를 갖추도록 할 것.
**[절대적인 재발 방지 대책 보고 및 즉시 수정 집행]**
 * **재발 방지 대책 즉시 보고:** 이번에 해결된 사항들과 과거/미래에 발생할 수 있는 모든 리스크에 대응하기 위해 구축된 영구적 방어 체계(아키텍처적 가드 레일, 상태 관리 원칙 등)를 명확히 보고할 것.
 * **보고와 동시 수정 강행:** 재발 방지 대책을 세움과 동시에, 시스템 내부에서 곧바로 코드 수정 및 최적화 실행을 완료할 것.
**최종 요구 사항:** 말로만 변명하거나 코드를 뱉어내지 말고, 지금 당장 시스템 내부에서 재발 방지 대책 보고와 동시에 기존 UI/디자인/로직의 변경 없이 과거·현재·미래의 모든 오류 수정, 런타임/로딩 단축 및 최적화를 완벽하게 끝마친 뒤, 그 실행 결과와 '수정 및 최적화된 코드 내역', '발견된 암묵적 오류 수정 결과', 그리고 '절대적 재발 방지 체계'를 개발자와 일반인 모두가 확실히 납득할 수 있도록 가장 심층적이고 상세하게 보고해라. 위 내용을 단 1개도 빠뜨리지마! 명심해.
